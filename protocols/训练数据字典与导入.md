# 训练数据契约

训练入口为 `python -m training.run`，运行位置是服务器 `/home/sysu/EEGMovement`。本机可以运行数据审计、因果预处理测试和 readiness 检查，不要求先安装 Unity。本轮不启动正式训练。

## 规范目录

`data/personal/manifest.json` 与它同目录的 NPZ 存放真实佩戴采集数据；未采集前不创建假的空训练集。NPZ只读取数值数组，禁止pickle。数组形状为 **[trial, time, channel]**。每个 trial 可先包含连续预热/准备段，结束于解码段末尾。当前训练器每个试次只取一个右对齐窗口；暂不隐式扩张重叠窗口。

Manifest顶层字段：

| 字段 | 约束 |
|---|---|
| schema_version | 1 |
| dataset_id | 独立数据版本标识；不同范式分别建数据集 |
| development_only | 开发样本true；正式数据仅在完成核验后设false |
| paradigm | ssvep或natural_intention；MI对照不得冒充自然方向 |
| labels | 按顺序REST、FORWARD、BACKWARD、LEFT、RIGHT；LEFT/RIGHT是转向 |
| sample_rate_hz / unit | 实测原采样率；单位只能是已核验uV或V |
| channel_names | 实际数组通道顺序，必须匹配设备profile，不得猜Ch1位置 |
| channel_map_verified / reference_verified | 核验状态，同时保存原始证据来源 |
| license_reviewed | 公共数据使用条款已按具体版本核验 |
| split_group | 个人数据用day_id或session_id；公开泛化先按subject_id |
| matched_idle / artifact_controls / cue_controls | 对应控制是否采集并审核；缺项时拒绝正式个人训练 |
| software_event_timing_reviewed | 软件事件与采样对齐方法已核验；不等于物理显示trigger |
| trials | 下表中的试次记录 |

每条trial的字段：

| 字段 | 含义 |
|---|---|
| trial_id | 全局唯一，不随窗口变化 |
| subject_id / day_id / session_id / block_id | 重新佩戴日期、会话与block边界 |
| split | train、validation、test；先分组，再预处理和窗口化 |
| label | 明确任务标签；invalid不等于REST |
| file / file_sha256 | Manifest相对路径与实际文件SHA256；不得越过数据目录 |
| array_key / array_index | NPZ数组名与trial轴索引 |
| start_sample / end_sample | 原数组中半开区间[start,end)，含连续预热；两端是实际收到的样本序号 |
| decode_start_sample / decode_end_sample | 只允许评分/建模的解码段；end应与end_sample一致，长度必须覆盖证据窗口 |
| content_sha256 | 截取后time×channel、little-endian float64连续字节的SHA256 |
| qc_valid / qc_reason | 人工与软件审查后是否纳入；保留排除原因 |
| discontinuous | 任何未处理缺包/跨来源/重置均标true，不跨缺口拼接 |

Manifest审计检查文件变动、同trial重复、内容跨集合重复、分组跨集合、源区间重叠、各集合类别覆盖与有效样本覆盖。设备profile在 `configs/training_device_profile.json`，其verified仍为false，实际线路、REF/GND和证据必须由真实核对填写。

## 采集和事件

现有hub原始JSONL是采集档案，不是可直接训练的试次表。先保留原始数据与独立事件日志，再人工/脚本对齐并导出上述Manifest。当前未佩戴/无任务标签的诊断录制不可转换成带方向标签的数据。

事件至少记录session、trial、paradigm、label、prepare/decode/rest阶段、sender monotonic、hub接收monotonic、sample_index_end、source_epoch、QC和trigger_type。跨进程/设备时钟先做映射，不能直接相减；收到软件marker不代表屏幕/头显已经呈现刺激。未实际测量前不得填硬件trigger精度。

原始接收序号是实际收到的样本计数。缺包/重置要保留断点，不能当成完整ADC时间轴。训练期预处理与未来部署适配器使用同一个 `training/preprocessing.py`；先分组，逐连续trial重置，不把验证/测试的滤波状态、归一化统计或未来样本泄漏到训练。

## 模型预处理

| 模型 | 输入与缩放 | 因果重采样附加FIR群延迟 |
|---|---|---:|
| Signal-JEPA | 128Hz，0.5–40Hz，uV；实测最少152点，默认比较1.25/2秒 | 250→128为78.125ms |
| CBraMod | 200Hz，0.3–40Hz，uV/100，完整200点patch | 250→200为50ms |
| 紧凑CNN | 250Hz，1–40Hz，uV，252/500/1000ms比较 | 同采样率为0ms |

均保留50Hz陷波，按各trial第一采样点去除固定DC，保持as-recorded参考。当前CBraMod适配器没有照抄作者部分任务的平均参考和整段傅里叶重采样，而是明确采用因果设备适配方案，应作为独立适配实验评估。SOS滤波群延迟依频率变化，尚未测定；表中FIR延迟不包含SOS、蓝牙、确认、证据窗口和渲染。每个trial要求至少2秒连续预热，再截取证据窗口。

## 已准备公开样本

`data/prepared/development/nakanishi_three_subjects/` 含s1/s2/s3，共540试次，以被试分配到开发train/validation/test。共同五点PO3、PO4、O1、Oz、O2来自公开采样布局，不是确认后的本设备线路。

标签为TARGET_01–TARGET_12。没有REST，没有四方向，没有速度标签；原始幅度单位和参考方式尚未核实，许可也未完成具体版本审核，QC未评定。因此这套样本能用于格式、切分与读取准备，不能通过当前正式个人训练入口，也不能用来验收自然运动意图或idle误触发率。

源文件位置、固定提交、哈希和来源链接保存在Manifest的sources中。本轮新增的s2/s3与prepared文件放在data目录，已有研究资料索引仍保留。

## 重新佩戴记录

每次摘戴新建placement_id，记录于trial元数据并关联placement_session_template.json结构的会话记录。测量偏移毫米数/角度只有实际测量后填写，未知时null。按日期/会话隔离，同时报告各佩戴条件的结果；左右脑区名义映射与物理编号见docs/electrode-layout-and-placement.md。训练集的随机增强不能作为新的独立重新佩戴样本计数。

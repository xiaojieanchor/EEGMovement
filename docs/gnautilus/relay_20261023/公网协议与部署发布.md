# 公网协议、部署与发布

2026-10-23接续：角色固定为EEG采集端和Quest，各最多一个活动设备；首次身份由中枢自动封装并交给客户端，无需用户管理公网配对文件。[当前实现与真机记录](../relay_20261023_followup/自动连接与页面恢复_20261023.md)覆盖下方首版的人工配对步骤，消息签名、缓存和停止契约继续适用。

## 消息与信任

外层 `eegmovement.relay.v1` 使用 WebSocket binary：4 字节网络序 JSON 长度、UTF-8 JSON、原始 body。JSON 上限 64KiB，body 上限 4MiB。EEG body 再装入既有流描述、块头与小端 float32 原始数值，不在云端滤波、重采样或推理。

身份包括 workspace、from、to、boot、seq、kind、stream、epoch、block_seq、digest、mac。body 用 SHA256，端到端 HMAC-SHA256 固定以换行连接前述身份字段与摘要；Hub 和对应设备持有 E2E 秘密，云端仅有独立的挑战认证秘密。TLS、云端认证和端到端签名分开验证。

连接认证回包确立 `route_server`。每个来源的已认证 boot 分配单调 `route_generation`，四通道共享同一代。接收方按来源保留当前代和 512 序号防重放窗口；旧代晚到拒绝，同代改 boot 拒绝。服务重启时四条连接必须对同一个新 route_server 重新认证；仅此时重置旧服务的路由状态。路由代元数据受 TLS 和认证服务约束，不代替 E2E 签名、接收端票据或样本稳定身份。

四条独立通道为 control、data、backfill、preview；更新走独立 HTTPS。Python 不在全局 Endpoint 锁里同步写网络，每条通道有独立锁和 5 秒发送截止。预览可丢帧；数据／控制队列满会显式断开重握手。云端上限 32 连接，认证地址表有界，分通道消息速率受限；每工作区一个活动 Hub。同一身份不能并发冒用其他 boot。

设备只向自己的 Hub 发规定消息；Hub 只能回复已登记设备。RPC 只允许源码 `hub/public_relay.py:RPC_PATHS` 中的记录、状态和意图接口，不接受任意 HTTP 路径。中枢仍通过现有本地模块访问内网模型服务器，公网程序没有此能力。

## 保存、确认与时间

云缓存 SQLite 使用 FULL/WAL，AES-256-GCM 密文独立 nonce 和稳定身份 AAD。密钥在 `/etc/eeg-relay/cache.key`；缓存文件在 `/var/lib/eeg-relay/cache/`。单块提交后 cloud_durable，Hub 原始日志持久化后 hub_ack；只有后者清除对应云缓存。采集端不因任何确认删除原始记录。

重复稳定块内容相同即去重；修改后的重复块拒绝。实时与补传可更换运输头中的 mode／ticket／source_age，但原始描述、样本和稳定头必须相同。Hub 拒收块保留隔离证据并反馈 hub_reject；云端相应行隔离，不再反复堵塞补传。AES 损坏逐行隔离，健康块继续。TTL 清理记录需要本地补传的审计。

实时资格由 Hub 发出的短期票据和采集端读数年龄保守计算，仍须满足 250ms 输入新鲜度。云端补传强制历史属性，既不建立新 epoch 的实时状态，也不触发动作。动作仍由接收端单调时钟签发原有 180ms 租约；云端不能续期旧动作。

EEG 和 Quest 每 5 秒执行 t0（端发送）／t1（Hub 接收）／t2（Hub 发送）／t3（端接收）测量，并向 Hub 提交报告。偏移估计为 `((t1-t0)+(t2-t3))/2`，往返不确定度取 `((t3-t0)-(t2-t1))/2`。结果保留测量时间。软件时钟映射不能证明无线硬件 ADC 时间，未知设备缓冲延迟仍未知。

事件记录继续保留发送、接收、会话、序号、epoch、阶段及接收时样本位置；新增 sample_association 表达由时钟误差及样本读数锚点计算的估计区间。缺锚点、跨 epoch、断流或不确定度不足以定位时保持未关联，不能生成精确采样结论。Quest 离线事件持久补交仅归档，不能补写未经确认的持续标签或触发动作。

## 服务部署与回滚

入口：Nginx 443（当前）＋18443（备用）；后端仅 `127.0.0.1:18767`。部署配置在 `deploy/eeg-relay/`，脚本为 `scripts/deploy_public_relay.py`。服务使用独立用户 eeg-relay、目录、systemd 日志，MemoryMax=1GiB、CPUQuota=100%、TasksMax=128；公网服务自身的出站被限制为 localhost。

部署先检查原有 `schisto-study` 与 nginx，上传独立 release、验证 nginx，再切换 `/opt/eeg-relay/current`。既有 `jile.ltd`／`www.jile.ltd` 的 SNI、域名证书和应用路由保留。裸 IP 默认 HTTPS 虚拟主机改为 EEG 专用 CA，这是本次可达入口的明确变化。

管理员只读排障：

```sh
systemctl status eeg-relay --no-pager
journalctl -u eeg-relay -n 100 --no-pager
curl -fsS http://127.0.0.1:18767/eeg/health
systemctl show eeg-relay -p IPAddressDeny -p IPAddressAllow -p MemoryMax -p CPUQuotaPerSecUSec
curl -fsS http://127.0.0.1:18765/study/api/health
nginx -t
```

`deployment.json` 记录当前 release、源码 SHA256 和回滚脚本。随次部署的应急回滚脚本停止 EEG 服务、删除新增 EEG nginx 配置并重载 nginx，保留原有站点；数据和原始记录不删除。若仅回退 EEG 程序，可将 current 指向已核对的 previous release 后重启，仍需检查新旧协议兼容性。

目前 `/eeg/health` 不含秘密，返回服务状态、缓存计数和损坏隔离故障。已隔离合成测试冲突块保留审计，不能误认为真实设备录制。缓存保留期会清理云端临时项，采集端和 Hub 证据仍独立保存。

## 签名发布

脚本：`scripts/build_public_release.py`、`scripts/publish_public_release.py`。离线发布私钥和专用 CA 私钥仅留在本机 `hub/runtime/relay_private/`，不上传云端、不装入包。不可变安装包先上传并核对大小与 SHA256；签名清单最后原子替换。相同文件名但不同内容禁止覆盖。后续版本必须改文件名、递增发布序号；Quest 还须递增 versionCode 并使用同一 APK 签名身份。

本机发布用 OpenSSH 保留服务器主机密钥检查和既有 agent 认证；`scripts/ssh_physical_pipe.py` 只为该公网 IP 的22端口提供单 socket 物理网卡传输，以避免本机 VPN 对大文件上传的影响，不修改 VPN 或系统路由。第一次发布的摘要命令引号错误在清单切换前终止；修正后对已完整上传文件重新核对 SHA，再继续发布，记录分别保留于 publish.log 和 publish-final.log。

清单是 `{payload: base64(原始UTF-8 JSON), signature: base64(RSA签名)}`，签名算法 RSA PKCS#1 v1.5＋SHA256。先验证原始字节签名，再解析平台、协议、版本、路径、大小和摘要；不对解析后重序列化的 JSON 验签。包 URL 只可在固定 HTTPS 主机的 releases/ 下。

更新下载支持 Range 续传、限速 96KiB/s、空间预检、完整摘要验证。Windows ZIP 限制总展开尺寸、文件数、路径穿越和符号链接。Windows 安装器等待主进程退出，原子切换版本，再核对新进程 PID 的健康回执；失败恢复旧指针。Windows 记录和配对不随版本覆盖。启动器自身随首个安装器部署，本轮更新协议管理工作台版本；未来若需升级启动器应发布对应安装器并保留兼容引导方案。

Quest 先校验离线清单，再校验 APK 包名 `org.eegmovement.workspace`、实际 versionCode 和 APK 签名证书 SHA256：`656c3b5b180f1cac817a881ed65642c04ac3f6b39fba2351f632094791e549ce`。系统可能要求许可或确认；安装请求、系统结果和新版本启动是不同状态。后续发布用更高 versionCode 前滚修复。

当前更新路径：`/eeg/updates/windows-x64.json`、`/eeg/updates/quest-arm64.json`。服务端检测清单变更通知设备，通知只能触发签名检查，不包含安装命令。即使通知伪造也不能绕过签名校验。

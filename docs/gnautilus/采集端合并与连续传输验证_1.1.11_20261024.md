# 采集端合并与连续传输验证：1.1.11

2026-10-24。基于中枢提交236bf6a合并。1.1.10签名包保持不可变，本机改进使用1.1.11。

## 修复内容

- 保留中枢提供的实时／补传独立线程、约一秒的有界SDK取数容量、错误16／17提示及补传先到时实时副本只发布一次的修复。
- 修复两个发送线程每5ms复制排序全部历史记录的问题，改为有序索引与独立游标，每轮最多检查64条。运行数千块后不再因全量扫描消耗CPU。
- 密集Qt抗锯齿描线在19秒实测剖析中耗时约7.3秒，改为单像素描线、100ms显示刷新、过期状态变化时单次重绘，包络计算向量化。原始float32数据、峰值顺序、NaN间断及配置不变，裁切只作用于显示。
- 开始接收请求会等待正在执行的后台任务，不再静默丢失；空闲状态连接不会覆盖上一流的未确认块数。参与者关闭允许10秒排空，并提供最多5秒中枢确认机会。
- 原厂参与者每80ms读取现有扫描，降低小帧开销；不修改原厂采样率、配置或设备启停。
- 中枢原先把旧状态票据的完整往返延迟计入新读样本的年龄，可能在块间误触发过期。现在在有效票据基础上，使用已有认证时钟交换的时间区间下界收紧估计，扣除时钟不确定度及漂移余量；过期时钟、未来时间或无票据仍不取得额外实时资格。原有250ms接收门槛继续在落盘后执行。
- 中枢回传relay_timing_policy、source_age_ms及last_source_loss，并在实际中断采集时记录原因。不能仅凭启动版本号认定远端加载了接收修复。

## 现场证据及限制

- 修复前一次真实采集约765秒、191251行，观测速率约249.96Hz，原始流完整封存，没有缺失块；此前六个真实流均取得中枢持久化确认，积压归零。
- 单独修复发送优先级仍未消除连续中断；有界扫描后的实测中，多数块进入实时缓存，持久化前缀紧跟，但现场仍报告1–2秒中断，因此不能宣布完整闭环验收通过。
- 1.1.11的中枢时间修复需要中枢拉取源码并实际重启后验证。隔离TLS/WSS的合成数组测试覆盖真实协议、标签、事件、原始存储及SHA校验，不代表远端真实打标已经通过。
- 新代码保留真正过期、缺口和失联时的停止边界，不把未知或未标注段补为REST。接触质量、物理电极位置和新模型有效性仍需单独核验。原始EEG、SDK、密钥及内部日志不进入公开仓库。

## 继续部署

两端拉取main；中枢需要重启实际后端进程。采集端可运行scripts/build_gnautilus_acquisition.py构建，再用scripts/install_local_acquisition.py安装到已有启动入口，保留身份和原始记录。开发安装不替换远端签名清单与反降级状态。

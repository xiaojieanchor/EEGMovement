# 连续眼动读出修复、重训与同输入开发对照

2026年10月25日。本轮修复已经进入真实A100训练，不再只是保存审阅数据。测试集本轮没有解码，也没有用于拟合或选参。

## 已修复什么，效果如何

**修复了新增眼动读出按短试次重复预热的问题。** 新入口从原始canonical流读取角色隔离的真实前后史，合并同源同角色的重叠连续区间，避免重复训练同一源样本。试次或标签变化不会清空状态；角色边界、真实缺口和电气QC拒绝仍然重置。每个训练／开发候选的UNKNOWN头尾都进入特征历史，但不被伪造为REST或方向标签。

配对训练完成：同样250次优化、同样正则化和特征，仅改变训练上下文。在同一连续开发输入上，**全32路＋10%额部的含拒绝宏召回37.93%→42.76%**；固定1秒指数平滑后41.69%→45.58%。额部单独读出29.73%→28.97%，没有受益。不能把全32路融合的改善改写为眼动头已全面识别可靠。

动作效果仍未达标。平滑融合版本虽然原始宏召回45.58%，在原固定保守动作规则下覆盖为0；没有降低阈值制造动作。因此本轮保留离线研究权重，未替换所选模型、未开启推理／Quest动作。

## 分类改善没有替代动作验收

固定保守动作规则未调参。修复后融合无平滑的开发动作覆盖约5.77%，接纳正确宏召回5.60%；固定1秒平滑的覆盖和接纳正确宏召回均为0。两者在23.1秒明确REST中观察到0次误启动，这只能描述该短记录，不能外推长期低误启动。

补查并修正了离线动作统计的另一个边界：连续输入不能按试次标签重置确认状态，统计响应试次时却要保留真实试次身份，不能把多个任务计成一个连续段。新增回归先复现错误，再修复；从已保存预测重新核算，零训练更新，原报告和原始权重保留。分类BA未因此改变。

## 实际实现和冻结合同

新训练入口为`gnautilus_ml.contextual_readout`。明确比较旧裁剪训练与连续上下文训练；连续输入请求前8秒、后3秒，遇其他角色／断流截断。不是直接读取上轮审阅用的前12秒／后6秒版本，也没有静默改写旧数据合同。

先核对原始数据、原模型与实际源代码身份，执行A100预检并锁协议，再训练4个正则线性读出：两种训练输入×额部156维／全32路1008维。每个250次真实优化，保留梯度、loss及安全NPZ。额部10%融合与1秒平滑是预先锁定的工程对照，不从测试选系数。原JEPA／公开迁移编码器作为冻结参照保留，**本轮不是重新训练JEPA主体，也不是原三种子计划的完整完成**。

实际训练／开发原始支持交叉为0；新增开发上下文与冻结模型真实私人监督、SSL抽样支持交叉也为0。协议为`931976e37dbb555806a37c7eec9be241c8846b63684f4c2face4d44dd62ffa5e`，真实实验约94.42秒。当前累计预算记账约11312.33秒，包含先前重复／负结果和保守上界，低于原43200秒上限；这不是精确GPU忙碌时间。

## 文献与结论边界

Nature Communications的个体手指BCI研究支持利用分布式头皮信号，也指出在线平滑主要改善稳定性，并未显著提高分类准确率；本轮因此把原始分类、输入就绪和动作门控分别报告。[原论文](https://www.nature.com/articles/s41467-025-61064-x)

Malta官方眼电范式区分向目标、返回和眨眼；当前头皮记录与独立EOG不等价。本轮没有同步眼位真值，起止按钮和UNKNOWN外的方向标签只能作联合任务弱监督，不能自动延伸成持续眼位坐标。[官方说明](https://www.um.edu.mt/cbc/ourprojects/eyecon/eogdataset/)

本轮已落实的是输入／状态边界修复、真实配对重训和完整回执。仍未落实的是：所有方向可靠识别、客观眼位及回中真值、跨佩戴泛化、独立新测试和真实Quest执行。后续优先保留修复后的连续全32路路线，额部辅助保持有限权重并继续作对照；需要新的完整独立联合试次和同软件REST确认本轮改善，不能继续用已查看测试调参。

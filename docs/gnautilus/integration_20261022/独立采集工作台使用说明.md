# g.Nautilus 独立采集工作台

Windows x64便携程序，目标电脑无需安装Python。请完整解压并保留EXE旁的`_internal`目录。运行`EEGMovement-gNautilus.exe`，不要单独复制EXE。此程序负责参加共享会话、显示、保存与转发；原厂软件负责配置和设备采集启停。

v1.0.1补充：中枢连接按配对JSON的IP／端口进行，不使用广播搜索。左侧“发现本机EEG设备”只查询这台采集电脑的GDS。必须先把中枢生成的配对文件复制过来并选择；新版在网络测试前显示文件是否有效及目标地址，未选择时直接提示操作步骤。详细修复见[连接问题说明](connection_fix_v101/连接问题分析与修复.md)。

## 第一次连接

1. 本机按原方式运行`python scripts/start_hub.py`。在本机8765页面填写采集电脑能访问的本机IPv4，生成采集端配对文件。把生成的JSON复制到采集电脑；配对文件包含凭据，不放进公开资料。
2. 采集电脑先完成原厂驱动、GDS服务和g.NEEDaccess Client API安装。用原厂软件配置并启动可参与的非独占会话；滤波、参考、采样率、通道均在原厂设置。
3. 工作台选择Client API目录、配对文件、本地保存目录。目录中应能找到C头文件及`C/x64/GDSClientAPI.dll`。点击“发现共享设备”，确认序列号；存在多个设备时填写本次设备序列号。
4. 点击“检查中枢连接”，依次检查TCP、TLS、身份与状态回传。通过只说明网络与身份有效，不代表电极接触或设备取数通过。
5. 点击“开始接收”。检查设备采样率、列数、本地已保存行数、波形和中枢持久化前缀。波形为空时不生成演示数据。接触质量未测量保持未知。
6. 在本机中枢或VR中开始主动标签任务。松开、失焦、暂停和未标注保持UNKNOWN；当前未配置模型，动作STOP是预期状态。
7. 先在中枢／VR结束标签会话，再在采集端“结束并保存”，等尾块关闭。最后由操作者在原厂软件停止设备。结束本程序不会命令设备停止。

## 波形和状态

- 最近5秒原始EEG，每页8路，统一µV量程；附加通道的身份和原值保存在数据中。限幅只影响显示；缺失值留断口，不重复滤波。
- “冻结显示”不暂停接收和保存；“减少界面动效”降低绘制频率并取消按钮过渡。窗口较窄时数值卡改为两列，其余内容滚动查看。
- 中枢回传显示实际记录行数、标签、阶段、VR在线数和模型停止状态。空闲连接测试是短暂快照，不能代替持续在线状态。
- 日志分采集、写盘、中枢各组件、校验与异常，支持筛选和JSON导出。界面日志有容量上限；完整数据提交及异常检查点保存在记录目录。

## 断网、补传和记录核对

断网时继续本地保存；恢复网络后自动重连，历史数据仅补传，不进入实时控制。若结束时仍有待确认块，保留目录，之后选择“补传已有记录”，指向含descriptor.json的流目录。补传完成后会显示全部块获得持久化确认。

本地默认记录位于`%LOCALAPPDATA%/EEGMovement/gNautilus/recordings/日期/streams/流ID/`；中枢原始流位于项目`data/gnautilus/日期/streams/采集端身份/流ID/`，主动实验会话另在sessions目录。原始流两端按同一流ID核对，不能把仅截取一段的实验会话当作全流比较。

程序提供只读核对命令，不会截断或修复文件。将结束后的同一流目录从中枢复制到采集电脑，使用以下命令；报告中的`complete_closed`与`comparison_match`应为true，同时检查missing_sequences和异常。实际物理追加顺序可能不同，因此比较逐块序号、样本位置与内容哈希，不强求两个raw.f32的文件哈希相等。

```powershell
.\EEGMovement-gNautilus.exe --audit "D:\EEG记录\本地流ID" --compare "D:\中枢副本\同一流ID" --report-path "D:\EEG核对.json"
```

只检查一端时省略--compare。未关闭或崩溃文件会标明未提交尾部，不冒充完整关闭；通过“补传已有记录”打开旧流时才进行明确的提交恢复。已提交块损坏会报错，不补零。

## 现场网络与故障

采集电脑主动访问中枢TCP8767，Quest主动访问TCP8766及签名UDP19771。原厂GDS只在采集电脑本机使用。下级路由NAT允许响应沿已建立连接返回；这不保证校园网／访客网络允许互通。先测目的IP和端口，再看TLS与身份，最后看数据新鲜度和VR回执。不可达时让三端接入同一路由/AP，再填写该网络下的中枢地址。程序不会自动改防火墙或路由。

启动失败查看`%LOCALAPPDATA%/EEGMovement/gNautilus/startup-error.log`。双击“依赖自检.cmd”只检查依赖，不访问设备。进一步诊断可用`--diagnose --sdk-dir "实际Client API目录" --report-path "报告.json"`；这只在独立进程发现设备，不启动设备。网络测试直接用工作台按钮。

磁盘满／写盘失败时程序报错并停止自身接收，保留已提交记录；原厂采集是否继续由原厂窗口决定。SDK无数据超过5秒会停止自身接收；强制退出与未提交数量会登记。电极接触、无线质量、Validation和计数异常分别判断。

真实设备取数、共享参与、Windows运行环境、校园网络和头显尚需现场验收。详细API生命周期、故障表、验收顺序及证据见随包《Python API与独立采集端接入说明》。

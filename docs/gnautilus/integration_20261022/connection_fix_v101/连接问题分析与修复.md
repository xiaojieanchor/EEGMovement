## 已确认原因

22:30:02至22:31:20多次出现`Permission denied: '.'`，之前没有TCP成功、TLS或身份事件。原程序将未选择的配对路径空字符串传给Path，得到当前目录`.`，随后按文件读取，复现了完全相同的Windows权限错误。它发生在socket连接之前，不能据此判断另一台电脑与中枢的网络是否可达。

同时，本机检查时8765／8766／8767均未监听，且尚未生成g.Nautilus配对文件。本轮已启动中枢并生成文件；当前WLAN地址为192.168.123.173，198.18.0.1是FlClash虚拟接口，不作为本次配对目标。Windows防火墙配置只读检查，没有修改。

日志中的“发现的共享设备：无”属于采集电脑本机的GDS设备发现，和中枢连接是两个入口。后续仍需在原厂软件建立允许参与的共享采集；本次没有远程检查或操作采集电脑的设备。

## 修复范围

- 配对文件在网络操作前核查：未选择、文件夹、不存在、权限、大小、UTF-8／JSON、对象类型、配对schema、身份、IP与端口均有可执行的中文提示；支持Windows复制路径时带引号。
- 工作台显示“未选择中枢配对文件”或已核实的目标IP／端口，附操作顺序；选择路径后及测试时保存设置，变更文件后清除旧测试快照。
- “发现本机EEG设备”明确只查询GDS，不表示搜索中枢；中枢按配对地址连接，不依赖广播，仍适用于下级路由NAT。
- 日志先记录实际连接目标，再区分TCP拒绝／超时、TLS证书和身份／状态回传。没有选择文件时不会虚报已开始TCP测试。
- 导出日志增加版本与安全连接上下文（是否选文件、是否有效、目标地址），不导出secret。TLS固定证书与挑战签名继续执行。

1. 退出旧采集端，将v1.0.1便携ZIP完整解压到新文件夹，保留_internal，打开新EXE。窗口标题和启动日志应为v1.0.1。
2. 将本机桌面的[gNautilus-pairing-192.168.123.173.json](C:/Users/19410/Desktop/gNautilus-pairing-192.168.123.173.json)复制到采集电脑。它是带凭据的配对文件，应单独转移，不放入公开日志或普通数据集。
3. 在采集端左侧“中枢配对文件”点击“选择”，选中复制过去的JSON；页面应显示`192.168.123.173:8767`。不要选择事件日志、SDK目录或文件夹。
4. 点击“检查中枢连接”。应依次出现TCP端口连通、TLS指纹匹配、身份通过和状态回传。此检查不要求EEG共享会话存在。
5. 网络检查通过后，再按原厂流程建立共享采集，点击“发现本机EEG设备”及“开始接收”。中枢连通不等于电极质量或真实取数通过。

## 若仍不能连接

TCP连接被拒绝：检查本机中枢仍在运行，8767监听，以及是否用了正确配对文件。TCP超时：核查两端IP、路由器／AP客户端隔离、采集电脑防火墙和校园网路由；必要时三端接入同一路由/AP。TLS指纹错误：核对是否连错中枢或文件来自旧证书，不能关闭证书验证。身份阶段关闭：核对旧程序是否仍占用同一身份、文件是否轮换。

本机已用实际WLAN地址完成TCP／TLS／身份／状态回传；此证据不等于已从另一台Windows电脑跨网连接。新版日志仍失败时可再次导出，按明确失败阶段继续定位。

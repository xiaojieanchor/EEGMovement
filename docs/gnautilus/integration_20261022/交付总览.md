## 本轮实现

数据流为原厂运行中的非独占共享会话 → 隔离SDK参与者进程 → 本地原始数据提交日志 → 主动TLS连接 → 中枢动态通道缓存及记录 → 电脑／VR主动事件 → 带样本位置的标签和保存清单。厂商高级pygds.GetData的设备启停副作用已通过源码识别；本程序使用受控CFFI允许接口，只控制自身streaming。

采集工作台提供实际原始波形、8路分页、最近5秒时间轴、固定µV量程、冻结显示、峰值保留、减少动效、分层连接检查及分项日志。中枢通过实际认证连接回传记录行数、标签阶段、事件保存、VR在线身份与模型STOP状态。展示截图使用明确标记的合成夹具，不是设备取数证据。

两端先持久化再确认；断网继续本地记录，历史补传不进入实时控制。块序号与内容防重复、提交尾部可恢复、只读audit可核对逻辑块摘要。配置／会话变化和断点以新流或epoch区分；松开、断流、页面退出和暂停不补REST。新入口不调用旧七槽解析、故障通道规则或重复滤波。

Quest与采集端都主动连接中枢，按签名身份而非设备IP绑定。UDP回包发往已认证心跳的实际来源端点，NAT映射变化先STOP再重新握手。TCP8767为采集传输，TCP8766为Quest API，UDP19771为执行签名通信，本机管理8765继续只在loopback。

## 最短现场操作路径

1. 在本机项目运行`python scripts/start_hub.py`，浏览8765页面，填写采集电脑可达的本机IPv4，生成并转移配对JSON。
2. 采集电脑在原厂软件配置并启动共享采集，完整解压便携ZIP，选择SDK／配对／保存目录，发现设备并检查中枢连接，再开始接收。
3. 核对实际设备、通道、配置采样率、原始值、本地增长与中枢持久化。接触质量仍按原厂流程核查，状态未知不冒充合格。
4. 在电脑或VR启动主动标签任务；先结束标签，再结束独立端并等待关闭，最后由原厂窗口停止设备。需要补传时选择原始流目录。
5. 对两端同一原始流运行--audit／--compare，核对块数、样本数、缺口、事件位置及SHA。现场网络不可达时先让三端接入同一路由/AP。

更新APK仅交付未安装。后续明确执行安装时使用`scripts/deploy_quest.py --serial 设备ADB序号 --hub-host 本机IPv4`；公共校园IPv4另显式加--allow-campus-host。Windows预览启动脚本已改为优先验证本轮构建记录和完整源码身份。模型尚未配置，不能把网络回包或软件回放当作运动意图识别通过。

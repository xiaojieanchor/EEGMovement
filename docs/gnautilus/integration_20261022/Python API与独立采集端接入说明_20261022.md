# Python API与独立采集端接入说明

2026-10-22 · g.Nautilus 32通道湿电极 · 补齐材料后的分析与实现

## 1. 本轮结论与阅读顺序

补充的软件包含真正的g.NEEDaccess Python Client API：pygds 1.20.1。此前的g.Pype参考不等同于此接口。当前最适合本项目的方式是：原厂软件配置并启动设备，独立Windows程序以参与者身份接收同一会话，通过主动TLS连接送入本机中枢；VR及电脑沿用主动事件打标，事件直接关联中枢收到的样本位置。

本轮实现不重做原厂滤波、CAR、DRL、量程或采样设置，不再次对取数结果应用旧设备滤波；模型尚未选定，运动输出保持停止。原始数据、设备传输有效性、电极接触质量与标签语义分别保存。软件测试、可启动安装包、原厂共享会话实测及实际头显验收是四类不同证据。

先看第2–4章理解材料和API；第5章解释新模板；第6–9章说明程序与中枢接口；第10章可直接带到采集电脑操作；第11章用于故障定位和实机验收。完整新增模型卡片另见[86个新增唯一模型逐项卡片](新增模型结构与迁移分析卡片_20261022.md)，不把通用库中独立的示例块误拼为同一个算法。

## 4. Python API逐层行为与本轮取舍

### 4.1 import不是无副作用的普通加载

pygds源码113–119行查询Windows服务GDS，191–341行解析头文件、构造CFFI定义、加载DLL并初始化。若GDS运行，包装默认选GDSClientAPI.dll；否则尝试GDSServer.dll。自动初始化失败或依赖路径不符应单独诊断，不能通过默认回退掩盖服务未启动。

本轮SDK模块导入不加载任何原厂库；只有独立SDK工作进程明确开始发现或接收时，才检查Windows x64、GDS已运行、用户指定的SDK头文件及x64 DLL。固定加载绝对路径GDSClientAPI.dll，不回退到GDSServer.dll，不启动服务。默认服务端127.0.0.1:50223，客户端127.0.0.1:0由系统分配空闲端口，不占用pygds默认50224。

头文件中的GDS_Initialize和GDS_Uninitialize返回void；pygds.Initialize返回True是包装层成功标记，不是原厂初始化函数返回码。pygds._chk首先判断返回对象是否存在，故不能只凭void与_chk并存认定原厂包装存在此项故障。程序对真正返回GDS_RESULT的函数核对ErrorCode与ErrorMessage。

### 4.2 发现设备不等于能够参与采集

pygds.ConnectedDevices在405–435行通过GDS_GetConnectedDevices取得设备分组及InUse。每个分组对应一个DAQ单元；多设备组必须保持原顺序及同步条件，不能把其中一个序列号当成任意独立设备打开。

本轮支持单台g.Nautilus。只选择InUse的g.Nautilus会话；多台可选时必须明确序列号。没有运行中的会话时提示先在原厂软件开始采集，不自动创建设备会话。发现与连接之间仍可能发生原厂退出的竞态，因此连接后还必须检查isCreator。

### 4.3 创建者和参与者是决定实现方式的权限边界

第一个打开设备组的客户端成为creator，可以配置及启动／停止设备；后续客户端只有在原会话非独占、设备组完全相同时才能成为participant。participant可以控制自己的数据streaming，不能控制设备采集或配置。原创建者退出会影响整个会话，参与者退出则只释放自己的连接。依据C手册PDF第10–11、26–27页及GDSClientAPI.h的GDS_Connect定义。

pygds.GDS构造函数960–1028行调用GDS_Connect时openExclusively为True，并自动读取配置。该构造方式不能直接作为本项目旁听器。独立程序明确以openExclusively=False连接；若返回isCreator=True，立即断开新建空会话，拒绝启动设备。原厂独占拒绝被保留为错误，不调用BecomeCreator绕过。

原厂g.Recorder手册能证明其使用g.NEEDaccess及配置入口，但没有证明当前安装、许可证及打开方式允许另一客户端参与。此项是实机首个检查点。原厂软件若始终独占，本版应如实拒绝；后续需选择支持共享的原厂流程或另行设计明确授权的创建者方案，不在当前程序里偷偷切换权限。

### 4.4 配置只读，不能把“无需配置界面”误解为“无需配置身份”

pygds.GetConfiguration在1047–1066行读当前配置；SetConfiguration在1030–1045行会改通道Acquire并向设备写入配置。独立接收端不调用SetConfiguration、SetScaling、Calibrate、ResetScaling、SetNetworkChannel或在线阻抗测量。

程序读取SamplingRate、NumberOfScans、InputSignal、CAR、NoiseReduction、通道Enabled、Sensitivity、BipolarChannel及原厂滤波索引。配套读取可用通道、滤波目录、Scaling、设备信息和支持采样率。滤波器索引要连同实际目录条目保存，不能把第几个滤波器当成固定截止频率。完整目录只保留计数与SHA，活动条目随描述保存，避免描述无限膨胀。

设备InputSignal必须是Electrode。测试信号和短路输入不作为真实EEG接收；原始数值已经由API提供为uV，程序不再应用Scaling乘除。Scaling及原厂设置作为可追溯元数据保留，不把不可测NaN强行转成0。

GDS头文件推荐NumberOfScans的注释出现500Hz，C手册表格出现512Hz；本程序查询实际支持列表与当前配置，不依据任一示例强制设采样率。原厂配置变化会结束当前流，不能热拼到同一模型输入。

### 4.5 一行是一次scan，不是一个通道的一批样本

GDS_GetData返回按scan连接的32位浮点数：对于N列，第s行第c列位于buffer[s×N+c]。EEG列单位uV；附加列有自己的量纲。请求buffer长度以元素数计，字节数为扫描数×列数×4，不将字节数误传给destinationBufferSizeInSamples。

本轮按实际Enabled且Available的物理通道顺序构造EEG列，随后依次追加已启用的加速度X/Y/Z、Counter、LinkQuality、Battery、DigitalIO、Validation。与GetDataInfo返回宽度必须完全一致，否则拒绝接收，不靠截断或补列消除错误。

| kind | 单位 | 解读及检查 |
|---|---|---|
| EEG | uV | 物理编号与实际位置分开；NaN／Inf保留原值，质量状态标异常 |
| ACC | g | 三轴附加量；用于头动观察，不能当EEG特征默认混入 |
| COUNTER | count | 原厂样本计数；检查连续性，未知回绕范围不猜填 |
| LINK | % | 无线链路指标，不是阻抗或电极接触合格率 |
| BATTERY | % | 电池状态，不作为脑信号质量评分 |
| DIGITAL | bits | 数字输入位编码；没有物理触发附件时不伪造硬件事件 |
| VALIDATION | bool | g.Recorder手册第70页说明1为无线样本有效、0为无效；不等于无伪迹或接触质量通过 |

设备固件可能返回电极名称，但当前帽子位置可调整，因此默认仍显示CH01等物理编号。仅在提供逐启用通道映射且verified=true时登记布局已确认；参考、地、佩戴ID未提供时保留null。

### 4.6 pygds.GetData便利函数为什么不能直接用于旁听

1265–1329行实现双缓冲及more回调；more必须复制数组，下一次取数可能覆盖该缓冲。1331–1364行的线程在入口调用StartAcquisition及StartStreaming，在finally中调用StopStreaming及StopAcquisition。参与者无权进行前后两项设备控制，因此本轮不调用该高级函数。

原包装还有需要处理的工程边界：内部线程异常被except捕获后不一定送到外层done队列；外层等待与join缺少明确时间上限。这里说明的是代码结构可能导致无法及时收到错误的路径，尚未在真实DLL上复现，不能当成原厂设备必然死锁的结论。

本轮CFFI只暴露读取、参与者streaming及必要回调函数；SDK进程一次读取容量约ceil(fs/20)，实际返回多少scan就提交多少。0扫描不产生假数据块，部分扫描不补零。取数结果立即复制为独立little-endian float32数组。

### 4.7 退出、变化与阻塞的处理

配置改变、设备采集停止、创建者退出或更换、服务器退出、强制关闭及采集错误回调只写故障标志；取数前后均检查。发生变化时结束当前流，重新开始生成新的stream_id。不会在回调中写文件、发送网络请求或调用可能阻塞的设备控制函数。

SDK运行在spawn子进程，便携程序入口调用freeze_support。监督器超过5秒没有样本会结束自身接收；退出先请求正常释放并排空已交付的尾块，再按时限terminate／kill阻塞进程。forced_termination进入检查点。原厂内部尚未交付Python的样本可能无法追回，不能据本地尾块保存宣称设备全过程无缺失。

关闭顺序是停止本客户端streaming、断开连接、释放配置及枚举列表、清理库。绑定保持回调对象存活，不在DLL卸载的静态析构阶段等待线程；原厂手册明确说明Disconnect应先于卸载。界面停止不会调用StopAcquisition，原厂窗口可继续采集。

## 5. 补齐后的Simulink逻辑，哪些值得移植

### 5.1 普通Bandpower模板终于能够与FES变体分开审查

新增M147 MotorImageryBandpower的四个带通功率实例为8–12、8–12、16–24、16–24Hz，阶数4，功率窗口设置为采集块的实际采样率，约对应1秒。之后是log10、WV加权和与偏置，再进入分类反馈。模板内WV的初始化不代表已训练分类器，更不代表个人效果。

可重实现的核心是因果带通状态、移动功率、对数特征、训练内标准化及线性判别，并完整绑定通道、频带、窗口和权重身份。不能直接把判别距离作为概率或行走速度。约1秒功率窗意味着新样本每50ms输出一次，也不等于50ms内积累了完整的动作证据。

### 5.2 二分类和三分类的在线窗口不是统一的1.5秒

M149二分类CSP选择W_CSP首2末2行，形成4分量，方差窗口为375个样本。它在250Hz下为1.5秒，在512Hz下约0.732秒；模板本身没有证明改采样率后仍保持1.5秒。首轮训练脚本VarianceWindowLength=1.5是另一个具体证据，实际移植前必须统一。

M148三分类包含三组CSP，各取首2末2，合计12个分量；方差窗以实际采样率表示。分组归一化及log10后进入分类器。不能把“12特征”当成12种控制动作，也不能凭三分类名称假设包含REST或UNKNOWN。

数学上空间投影z=W×x，常见对数归一化方差为log(var(z_i)/sum_j var(z_j))；实际底数及分组由模板确定。对数底改变可由重新训练的线性权重吸收，但导入原厂权重时不许擅改底数或归一化分组。CSP、标准化、特征筛选、窗口选择与阈值均需在相应训练划分内拟合，不能只对末端LDA交叉验证。

### 5.3 新蒙太奇与受保护函数解决的是依赖，不是效果证明

补齐的30ch_Nautilus蒙太奇确有30个电极名称：Fz、FT7、FC5、FC3、FC1、FCz、FC2、FC4、FC6、FT8、T7、C5、C3、C1、Cz、C2、C4、C6、T8、TP7、CP5、CP3、CP1、CPz、CP2、CP4、CP6、TP8、Pz、POz。它是厂商示例蒙太奇，不证明用户32路应扣掉两路作为参考／地，也不覆盖原报告的32点候选布局。

artifactDetection.p与plotOnly4CSPs.p可作为依赖登记，但前者内部的伪迹判定、拟合范围及后者显示选择的确切处理仍需原厂说明或运行验证。三分类MAT中的z1可读为三行45列的类别编排示例；不能因此把当前项目数据自动赋成相同标签。

### 5.4 从库中借鉴接口和闭环，而非直接打开全部控制模板

新增预处理、信号质量、变换、LSL及UDP库提供了参数接口和示例。它们帮助追踪主模板到底调用哪一层，而不意味着本项目已经具备受保护分类器、专有许可证或外部硬件。EMG/EOG模板可作为早期辅助控制基线，必须记录动作／眼动来源；不能将肌电或头动造成的可分性称作自然运动意图识别。

优先移植带身份的原始数据、逐级特征契约、因果状态重置、拒识及连续决策接口。需要改造的是投票／保持逻辑、无控制检测及跨佩戴验证。SSVEP／P300是有刺激依赖的备选输入；fNIRS、FES、眼动仪等额外设备相关模板只保留结构分析，不因安装包存在而启动硬件输出。

全部新增模型的用途、输入输出、真实连线、参数、回调、S-Function及项目建议见独立卡片；每张卡片链接完整structure.json。可见结构支持“可实现什么接口”的判断，不能代替真实准确率、自然意图有效性或跨会话收益。

## 6. 当前实现的数据流与身份

```text
g.Nautilus → 原厂GDS共享会话（原厂负责配置与采集启停）
            → SDK子进程（只参与、复制float32）
            → 有界队列 → 采集电脑原始日志
                        → 主动TLS连接 → 中枢原始流日志
                                     → 新设备缓存／状态
                                     → VR或电脑主动事件 → 带样本位置的会话记录
```

以上是本轮软件结构。真实原厂共享能力和真实设备取数仍待采集电脑确认。

gnautilus.stream.v1描述包含stream_id、epoch、设备序列号、来源、实际采样率、每列kind／unit／physical_index、配置及SHA、实际布局核实状态、参考／地／佩戴ID和未分配的数据角色。每个块保存seq、sample_start、sample_count、列数、<f4类型、数据SHA、取数单调时间及UTC观察时间。

sample_start是本流实际交付行号，不填补设备丢失的扫描。设备Counter原值另列保存，因此“已收到行号连续”不能代替“设备计数连续”。设备配置变化创建新流；运输缺口或Counter异常结束当前标签区间并重置中枢epoch，原始缺口仍保留。

未来模型输入接口返回流身份、epoch、实际采样率、完整列身份、配置SHA、样本末端及独立float32数组。execution_eligible恒为false直到后续新模型及质量规则单独实施，当前不会把二分类margin伪造成旧五／九分类概率。

## 7. TLS、NAT与两条不同的传输路径

采集端主动连接中枢TCP 8767。帧由4字节网络序总长、4字节JSON头长、UTF-8 JSON头及可选原始float32体组成，总长最大4MiB，JSON最大64KiB。TLS固定服务端DER证书SHA256，发送配对凭据之前先核对证书；每连接使用新挑战及agent_id／boot_id签名，不依赖源IP认证。

实时块与历史补传明确标记。中枢发短期新鲜度票据，接收时同时核对票据年龄与采集端报告的取数后时长，默认250ms界限用于防止积压被误当实时；它不是硬件采样到VR呈现的实测延迟，也不能防御已受信任采集程序故意伪造数据。

ack区分收到的块序号与连续持久化前缀。高序号先到可以入库，但durable_seq只推进到没有缺口的位置。相同内容重传幂等，改变内容的重复块拒绝。迟到块、补传块及重复块不刷新实时样本位置，不进入在线缓存。断网时本地继续落盘，之后通过原流身份补传。

VR继续主动请求中枢TCP 8766并发送UDP 19771心跳；中枢向已认证心跳的真实源端点回复。HTTP和UDP配对身份保留签名、启动身份与重放检查，不再把下级路由WAN地址当作唯一设备身份，同一NAT后多个设备使用不同凭据。

UDP接收端原有票据和时效保持。NAT映射改变时先停止并更换nonce重新握手，不给旧票据续期。校园公网IPv4只有在显式配对参数允许时才作为目的地址，管理界面仍限于本机。广播发现、手动端口映射及公网中继都不是本轮默认依赖。

“同一校园网”不保证互通：下级路由NAT通常允许内部主动连出，但校园客户端隔离、ACL或Windows防火墙可能阻断。先测TCP，再测证书和身份，再看EEG与VR回包。若网络禁止连出，应把三端接入同一路由/AP；程序不会宣称能绕过网络隔离。

## 8. 原始日志、会话、标签和恢复

每条原始流保存descriptor.json、raw.f32、blocks.jsonl、events.jsonl和关闭时的closed.json。先追加数据并fsync，再追加带偏移、长度、块头和SHA的提交记录并fsync，之后才确认durable。恢复时只承认完整提交；未提交raw尾部和半行索引／事件尾部被截去，已提交内容损坏明确拒绝，不悄悄修复为零。

网络日志保存采集端全流，中枢主动会话另按日期／sessions／会话ID保存。会话内原始矩阵从本会话第0行开始，块头的source_seq／source_sample_start保留原流位置；事件sample_index_end使用原流行号并带source_epoch／stream_id，不将两套行号混为一谈。

主动标签保留提示或按住语义，不把标签称为已确认神经意图。松开、未标注、失焦、暂停与断流不自动补REST。事件重试只能发送相同序号和相同内容；会话、阶段、方向及来源均检查。采集断流或发送端超时结束标签区间并关闭会话，部分数据仍保留。

关闭清单记录块数、样本数、缺失序号区间、恢复尾部字节数及文件SHA；数据目录catalog只索引，不授予训练或独立验收身份。wearing_id未知保持null，role保持unassigned。原始数据从未用于本轮训练。

便携程序的--audit与--compare为只读核对入口：核查完整提交块、事件JSON、关闭清单、数量及SHA，标出未提交尾部；比较同一原始流时按seq／sample_start／sample_count／块SHA计算逻辑摘要。网络先发最新块再补历史，可能导致两端raw.f32物理追加顺序不同，不能仅凭整文件SHA不同认定数据改变。单独截取的主动会话与全流不作等长比较。发现已提交损坏即报错；未关闭文件不声明完整验收。同一采集端与stream_id跨日重连仍复用最初目录和持久化前缀，不按新日期重建；若发现多个冲突目录则报错要求核对。

采集端写盘失败会停止自身接收，记录或显示错误及尚未提交的队列数量。SDK强制退出、网络积压、中枢过期与电极接触未测量各自列项，不能全部归为“脑电质量差”。

停止自身streaming或释放SDK资源失败时，中枢与本地检查点保留错误，采集端结束状态为需要检查；隔离进程被强制终止也不显示正常释放成功。已持久化数据可以关闭保存，但“文件关闭”与“SDK正常释放”分别核对。

主机时效使用SDK调用开始的read_monotonic_ns及结束的read_completed_monotonic_ns记录整个观察区间；UTC同样保存开始和结束。原厂调用、状态核对、复制、进程排队、本地落盘和中枢落盘均消耗实时预算。中枢在提交完成后重新检查时效，向实时缓存传递剩余预算，不从入库时刻重启250ms计时。过期块保留原始记录，但不刷新实时状态。SDK内部已有积压与硬件采样到主机之间的绝对年龄仍未知，需设备现场测量，不能把主机新鲜度当作硬件端到端延迟。

## 9. 中枢与VR接口及停止边界

| 入口／组件 | 行为 | 检查边界 |
|---|---|---|
| 本机根页面 | 默认显示g.Nautilus连接、动态通道波形、记录和电脑按住打标 | 本地管理，不对校园网开放 |
| GET /api/gnautilus/status | 采集端连接、持久化、积压、当前描述及实机待验状态 | 不返回密钥和原始EEG |
| POST /api/gnautilus/pair | 按明确本机IPv4生成本地配对文件，启动TLS监听 | 返回文件路径，不把secret显示在界面 |
| POST pause／resume | 暂停中枢实时接收和标签，或恢复接收 | 不改变原厂采集设置；传输日志仍可持久化 |
| 既有acquisition start/event/stop | 新鲜真实流上创建提示或按住标签会话，原样保留事件序号 | 同时只允许一个标签会话；合成流不得创建个人采集 |
| record start／stop | 创建无标签原始会话或关闭保存 | 不能借此恢复旧模型入口 |
| Quest状态schema 3 | 返回完整受控通道列表、实际／标称频率及接触质量未知 | 不截为七路、不显示伪造的绿灯或0%模型成绩 |

VR执行端的急停、失联停止、接收端验证及原有时效票据保留。采集中暂停模型执行；原厂窗口继续采集不等于VR允许动作。新设备质量规则没有沿用旧CH1／CH6故障和“至少4路绿灯”数值。

采样率显示来自原厂实际配置，不伪称主机实测到达率。新入口的configured_sfreq／nominal_sfreq为配置值，sfreq_measured保持null；Quest的sample_rate为兼容显示采用配置值，并以sample_rate_source=device_configuration注明来源。吞吐率和硬件时钟精度仍需现场独立测量。

## 10. 现场操作顺序

### 10.1 本机中枢准备

结束旧中枢进程后按原项目启动方式重新运行hub.app，浏览本机8765页面。填写采集电脑能访问的本机IPv4并生成配对文件；复制该JSON到采集电脑。配对文件包含凭据，不作为普通实验附件公开。不要复制server.key到采集电脑。

需要放行时，在Windows防火墙中针对程序及实际网络范围允许TCP 8767、TCP 8766与UDP 19771。程序不会自动修改校园路由器或系统防火墙。若地址发生变化，重新生成或更新配对文件中的目的地址并核对证书身份；密钥轮换需要重新配对。

### 10.2 采集电脑准备

先按原厂手册安装驱动、GDS和Client API，确认实际Windows x64。将便携ZIP完整解压，保留EXE旁的_internal目录。目标电脑不需要额外安装Python，但仍必须有原厂设备驱动、服务及DLL依赖。

在原厂软件选择g.Nautilus，按实际实验要求配置通道、采样率、滤波、参考及附加信号。建议检查Counter和Validation是否可用；没有启用的指标会显示未知，程序不会擅自替你启用。启动允许参与的共享采集会话，保持原厂窗口运行。

打开独立采集端，选择Client API目录、中枢配对文件及本地保存目录。发现设备并确认序列号，先检查中枢TCP／TLS／身份，再开始接收。若需要实际位置身份，另提供layout JSON；没有文件时保持CH编号及布局未核实。

### 10.3 开始与结束实验

先确认独立端样本持续增加、本地目录可写、中枢有新鲜数据，实际列数与原厂配置相符；然后从电脑或VR启动主动标签会话。按住代表该条指令的标签，松开为未标注；不能把操作按钮引起的运动伪迹忽略掉。

先结束并保存标签会话，再结束独立端接收；最后由操作者在原厂软件停止设备。独立端结束时等待尾块写盘，核对中枢持久化前缀。若还有积压，保留本地目录，通过“补传已保存记录”选择含descriptor.json的流目录；补传期间不作为实时采集。

命令行可使用--version、--smoke-test和--diagnose。smoke-test只检查程序依赖，不访问原厂服务或设备；diagnose在明确给定SDK路径时才通过隔离子进程发现设备，不启动设备采集。

### 10.4 采集工作台与波形判读

采集端使用PySide6原生窗口：左侧保留SDK、序列号、配对、保存及实际位置文件；上方提供连接检查、开始接收和结束保存。四张数值卡分别显示本地已提交行数、实际配置采样率、待确认块数与中枢持久化前缀。窄窗口将数值卡改为两列，内容可滚动；设置仅保存路径，不复制配对密钥。

波形显示最近5秒实际EEG，每页8路，按通道身份分页；附加通道保存在原始矩阵及描述中，不混入µV坐标。量程可选择±50／100／200／500／1000µV，同屏统一，不按各通道幅度自动缩放。超出显示范围时标明“限幅”，存储原值保持不变；NaN／Inf留断口。显示用按时间顺序的最小／最大包络保留短峰，不以抽点漏掉尖峰，不重复滤波、不补造信号。波形停止更新后变灰。冻结只固定图形，后台接收与持久化继续。

悬停采用150ms颜色过渡，不改变按钮位置；波形定时重绘目标约60次／秒，减少动效后约20次／秒，取数和显示分线程。以上是界面调度目标，实际流畅度仍取决于采集电脑；本机离屏绘制测试的耗时记录在verification/ui/review.json，不能据此承诺目标电脑持续帧率。

“检查中枢连接”逐层记录TCP、固定证书TLS、挑战身份和状态回传。接收期间使用当前认证连接，避免占用同一采集端身份的第二条连接。空闲测试返回的是快照，5秒后退出当前状态区；历史通过日志保留，不持续冒充在线。中枢主动回传记录状态／已保存行数、当前标签／阶段、VR在线身份数及模型停止状态。界面不根据“联网成功”推断电极合格或模型就绪。

分项日志区区分采集、写盘、中枢、校验和异常，支持筛选及UTF-8 JSON导出；网络失败和写盘失败分别显示。UI仅保留有界最近日志，原始数据提交与异常检查点另在数据目录持久保存。界面设置、导出日志和包内模板不包含配对secret。启动异常会生成本地startup-error.log并给出路径。

## 11. 故障定位与实机验收

| 现象 | 首先核查 | 正确处理及保留证据 |
|---|---|---|
| 找不到设备 | 驱动、设备电源、GDS服务、SDK路径 | 原厂软件先确认，保留发现错误码；不运行测试信号冒充EEG |
| 设备空闲或独占 | InUse、原厂会话权限、同一设备组 | 原厂开始共享；独占保持拒绝，不自动接管 |
| ABI／DLL失败 | Windows x64、头文件、DLL版本及依赖 | 保留哈希与错误；不随意从另一版本目录混拷DLL |
| 数据宽度不符 | Enabled／Available、附加列与GetDataInfo | 停止接收并核对配置，禁止截断成32或补零 |
| 中枢连接失败 | 中枢IP、TCP8767、路由／防火墙 | TCP层先诊断；校园隔离时调整为同一路由/AP |
| TLS或身份失败 | 证书指纹、配对文件、是否连错中枢 | 重新核对配对，禁止关闭证书校验继续传输 |
| 本地增长、中枢无实时 | 网络、积压、过期块、暂停状态 | 本地日志保留，补传不刷新实时状态；检查新鲜块 |
| VR有HTTP但无动作回包 | UDP19771、旧APK、nonce与端点变更 | 使用更新构建并重新握手；模型未配置时STOP为预期 |
| Validation为0／Counter跳变 | 无线传输、实际附加通道 | 保留原值和断点，结束当前标签区间，不填补样本 |
| 接触质量未知 | 本版没有连续阻抗读取或已验证新QC | 原厂流程检查电极；不把LinkQuality作为接触合格 |
| SDK无响应 | 超过5秒无样本、关闭回调 | 隔离进程限时退出并登记forced_termination |
| 磁盘满 | 两端剩余空间、写入错误和队列 | 停止自身接收，不静默丢块；保留已提交数据 |
| 会话关闭失败 | 提交索引、关闭清单及未完成尾部 | 用恢复入口核查；已提交哈希损坏必须报错 |

实机验收依次完成：原厂非独占共享；实际32路及附加列核对；10分钟无标签记录；电脑方向按住／松开；VR提示与主动标签；拔网后本地保存与恢复补传；原厂停止／退出；独立端结束不影响原厂；中枢停止与VR失联停止；最后核对两端数量、缺口、标签位置和SHA。

通过标准是流程和数据身份正确，所有缺口与错误均可追踪；此阶段不设置自然意图准确率门槛。实际反应时间、软件事件传播和中枢取数存在误差，当前标签采用主动记录语义，不宣称精确对应视觉刺激物理呈现时刻。

## 12. 可复核交付与尚待确认

程序源码在项目gnautilus_acquisition及hub/gnautilus相关模块，SDK绑定允许清单、块契约、持久化与NAT测试均可读。构建和测试记录见[verification目录](verification/)，最终验收摘要以其中delivery.json为准。原厂DLL没有随便携包重新分发，设备服务、硬件和许可证仍由采集电脑的原厂安装提供。

仍待实机确认的是：原厂软件允许参与的打开方式，当前帽子的实际接线／参考／地、支持采样率与配置，硬件Counter的回绕行为，真实无线断流表现，采集电脑运行环境与校园网络，以及头显安装后呈现。它们不由本机模拟测试或生成的APK代替。

后续新模型应以本轮带身份的实际会话作为输入，按完整日期／佩戴／会话分组，单列长时间无控制、持续保持、切换与停止的指标；开发集、软件回放和独立真实验收仍分别报告。

# 推理等待状态与持续提示修复（2026-10-29）

## 原因与行为

A100 连通、模型已加载、推理模式已开启，与是否有合格预测是不同状态。空载或未接好电极时，信号仍可传输，但当前模型的电气质量检查会拒绝输入，不能由“有数据”推断“有有效预测”。本轮不改阈值、权重、原始单位或预测有效性。

原实时总览把 `server.last_error` 直接放进红色错误行；模型预测拒绝会写入该字段，后续健康请求又清空它，于是文字反复出现／消失。推理页还优先显示技术就绪文案，掩盖实际输入拒绝原因；动作按钮在没有新鲜结果时仍可点击，然后被后端拒绝，看起来像没有反应。

## 修复

- 总览独立读取推理状态，以固定位置、稳定最小高度的状态说明显示“推理已开启 · 等待有效脑电”。正常质量等待使用静态中性色／低强调提示，不作为连接故障反复告警。内容只在状态变化时更新，`aria-live=polite` 不重复重建相同文字。
- 计算服务在线时，健康查询不能清空推理等待原因；真实计算连接失败仍单独报告。短暂查询失败保留最后回传，过期后明确标注等待更新，不推断模式已关闭。
- 推理页分别显示未开启、质量等待、预热、迟到、合同不匹配及运行中。技术连接就绪不能覆盖质量等待原因；停止推理始终可用。
- 缺少有效推理结果时，动作按钮明确显示“等待有效信号”，同时展示不能启用的原因。真正启用后按钮有明确选中颜色和 `aria-pressed=true`；关闭动作在结果过期时仍可操作。
- 沉浸式页面同步显示持续状态说明、具体平线通道数量及动作不可用原因。原导航和页面结构保留。

## 验证

14组 JavaScript 测试全部通过；补充反复交替健康成功／预测拒绝时文字不闪烁、不消失的回归，信号恢复后自动切换到运行说明；覆盖质量等待下按钮禁用、已授权动作仍可关闭、零隐式动作请求。真实总览页面已看到固定中文提示。

本轮仅修改网页脚本、样式及相关测试，无需重启中枢、采集端或A100服务，不关闭已经开启的推理模式。刷新相关页面后使用新界面；有效信号与真实动作效果仍分别检查。

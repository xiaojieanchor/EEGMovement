# 截图中的旧版配对入口与Windows1.1.3修复

后续勘误：用户运行的可能正是新版Setup，但1.1.3安装器默认双击会沿用旧安装指针。已在[1.1.4安装器修复](../setup_upgrade_fix_20261023/双击Setup升级修复.md)解决。下文“不要打开旧EXE”不足以解释该问题，请改用1.1.4安装器。

2026-10-23。

## 判断与原因

用户截图窗口标题明确为`v1.1.0`，侧栏有“中枢配对文件”，上方显示“未选择中枢配对文件”，日志反复要求从中枢复制JSON。该旧版在读取身份之前结束连接检查，因此截图不能证明公网不通：尚未进入网络连接阶段。

上一轮已发布1.1.2，但那台电脑运行的是旧程序。此前1.1.1／1.1.2还保留了折叠的“高级 · 局域网兼容”文件入口，未满足用户完全不管理配对文件的要求，本次一并删除。

旧1.1.0更新器要求收到新鲜中枢回包、记录关闭和动作STOP才能下载／安装；没有完成旧配对时无法取得该状态。公网发布新包不能修改另一台电脑已经运行的旧EXE，因此需在采集电脑运行一次本次安装器。后续由新版自动领取内部身份与检查更新，停止规则保持。

## 本次修改

- Windows版本提升为1.1.3，更新序号11003；Quest仍为已安装的2.1.2／21003。
- 删除配对文件的输入框、选择按钮和局域网兼容复选框，不保留隐藏控件。
- 启动后固定按EEG采集端角色自动连接。所有历史配对路径和明确的旧局域网设置均自动迁移；SDK目录、设备序列号、保存目录和原始记录保持。
- 本机身份只作为应用内部状态，不接受用户指定身份文件路径。内部信息损坏时备份后重新自动领取，显示自动恢复提示，不要求复制或选择JSON。
- 新版继续提供波形、日志、连接测试、独立原厂streaming和保存，不改变原厂配置或设备采集启停。
- 中枢页面的原布局和样式、本轮已经运行的Quest均不改动。

对应源码：`gnautilus_acquisition/qt_gui.py`、`__init__.py`，构建版本入口` scripts/build_public_release.py`。底层旧局域网组件和历史记录保留，不在当前工作台提供手动配对流程。

## 采集电脑操作

1. 停止本客户端接收并完成保存，关闭图中的v1.1.0程序。
2. 运行[EEGMovement-Setup-1.1.3.exe](../../../outputs/relay_20261023/release/EEGMovement-Setup-1.1.3.exe)。该程序不安装或修改原厂驱动。
3. 从新建的“EEGMovement采集工作台”桌面入口打开；标题应为**v1.1.3**。不要再打开旧解压目录的EXE或旧固定版本快捷方式。
4. 本机中枢在线且停止、记录关闭时，采集端自动连接并测试回包。界面不会出现配对文件位置。再按原厂共享采集步骤接收EEG。

便携版本见[Windows1.1.3 ZIP](../../../outputs/relay_20261023/release/EEGMovement-Windows-x64-1.1.3.zip)，自动切换版本建议使用安装器建立的启动入口。升级失败保留上一版本和数据；不要卸载原厂软件或删除记录目录解决连接问题。

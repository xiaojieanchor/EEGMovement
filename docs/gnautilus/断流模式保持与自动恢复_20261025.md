# 断流模式保持与自动恢复

按用户 2026-10-25 新要求：数据中断／丢失不退出已开启的打标和推理模式，恢复后自动继续。此前“网络异常直接关闭模式”的行为由此覆盖。

## 状态和约束

- 打标：活动会话 → 等待输入（active 保持 true，标签 UNKNOWN）→ 新鲜输入恢复 → 接收新的按键事件，或根据恢复后新鲜的按住心跳开启新的区间。中断区间绝不补写标签；旧会话不反复创建文件。
- 推理：已手动开启 → 等待输入／计算服务（开启意愿保留，输出清空）→ 原模型的新租约和完整新窗口 → 自动恢复推理。
- VR 动作立即停止并撤销允许执行，恢复后需手动重新允许；不回放旧动作。
- 手动停止、急停、关机保持明确停止，不自动恢复。模型切换仍停止旧模型，不能隐式加载其它模型。
- 真实新流或配置变化时，记录分段并保存清单；逻辑采集会话可保持，不能向旧输入合同的文件写入新流。
- 保持 250ms 数据新鲜度、因果预热、原厂参与者权限、UNKNOWN 和标签来源身份。公网故障不影响当前热点采集。

## 实施计划

1. `hub/acquisition.py`：增加暂停／恢复输入状态，保存标签终止、UNKNOWN 边界和恢复事件；超时只暂停，显式结束才关闭；适配恢复后的新鲜按住心跳。新增故障注入测试。
2. `hub/gnautilus_runtime.py`：按临时断流与显式结束分类处理，保持记录／采集模式；输入合同变化旋转文件；继续重置推理证据。验证缺包、断开、新 epoch 和停止。
3. `hub/ml_runtime.py`：暂停推理但保留开启状态，恢复时重新申请原模型租约；手动停止和迟到回包不能重新启动。使用隔离计算接口测试，不恢复旧模型或启动训练。
4. 保留原页面，展示等待输入／恢复状态；与固定 8768、1.1.14 票据时间修正一起回归、打包、推送。区分合成验证与真实设备、真实模型验收。

采用现有 Python／SQLite／WebSocket／SSH 架构，不新增服务或改动公网代理边界。

## 已实现的恢复边界

- `pause_input`／`resume_input` 保持采集 `active` 与会话 ID，在事件文件中保存暂停、恢复和 UNKNOWN 边界。手动停止仍关闭记录。新数据流会旋转物理记录文件，保持同一逻辑采集会话。
- 接收端确认不把已关闭会话重新建为新会话；中断期间收到的标签只作为等待观察记录，不能开始方向区间。恢复后的有效按住心跳从恢复点开始新的区间。
- 推理暂停清除结果、窗口和旧租约；原模型及完整新窗口就绪后自动申请新租约。迟到回复、手动停止和模型身份变化均不能偷偷恢复错误模型或动作。
- 页面和 Quest 动作允许接口均拒绝在等待／预热期间预先允许动作；恢复后重新允许才能执行。
- 相关计时、连接及采集端状态修正由 1.1.14 安装包交付，公开包不含凭据、原始数据或厂商 SDK。

真实兼容模型尚未完成现场推理验收；恢复推理能力以隔离故障注入与软件闭环验证，不冒称真实识别效果。断流片段不补为 REST，也不自动加入训练。

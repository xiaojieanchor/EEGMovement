> 本手册原正文为API提供前的准备阶段。现在已补充真正pygds／C API分析及数据全链路实现，参见文末更新；原离线实验和候选布局继续保留，实机配置不得由候选自动推断。

## 1. 路线已经收束：用运动区信号建立基线，逐步走向自然意图

主推荐采用**布局A：以FC／C／CP感觉运动区为中心的32个头皮点位**。第一模型选择正则化CSP＋收缩LDA，以双频带功率为更简单的参照。先回答信号是否稳定包含任务信息，再研究自然前进、转向、保持与停止。早期允许手脚运动想象或眼动辅助映射，但原始标签、模型能力与最终VR命令各自保存，不能把“右手想象分类”直接称为“自然右转解码”。

现有中枢、VR与控制接收器继续保留。Python API提供后才实施采集、服务与实际控制链路。本轮已构建独立`gnautilus_lab/`研究核心：输入合同、因果特征、CSP／LDA数值模型、按组／嵌套评估、指标与离线决策模拟。真实EEG训练入口仍关闭；测试使用合成数值，不读取新录制、连接设备或执行厂商程序。

最先需要的成功证据不是漂亮的分类图，而是：新日期／新佩戴的输入仍出现可重复的任务支持；信号来源有对照；长期不操作时不会持续误动；拒识、坏质量、预热及失败时段都在报告中。任何一项不成立，先定位原因，不以扩大网络、混入公共数据或降低门槛补救。

| 决策 | 本次选择 | 成功证据与边界 |
|---|---|---|
| 电极布局 | A为主；B只在专门眼动辅助比较时使用 | 两套各32个互异点位；尚未映射设备端口，换布局算新佩戴／配置 |
| 第一分类模型 | 正则化二类CSP＋收缩LDA，先左右手MI | 原生任务与NC另外定义；二类模型不冒充四方向自然控制 |
| 自然启动 | 独立因果低频MRCP候选分支 | 不能用8 Hz高通后的数据研究；动作前提前量必须实测 |
| 连续控制 | 模型分数与决策层分离，显式NC／拒识与停止 | margin不是概率，概率也不是主观速度 |
| MATLAB | 合法环境中的离线参考可选；暂不默认封装整套Simulink服务 | 本地P-code／MEX和示例批处理存在需核实的限制 |
| 公共数据 | 六组候选逐项登记，全部未准入训练 | 先方法验证，严禁任务换名／镜像重复／未经审核预训练 |
| 新版资料 | 已取得官方g.Pype 4.1.0相关示例与记录 | 未取得新版g.HIsys安装包；Simulink宿主R2026b不等于g.HIsys新版 |

## 3. 怎样预先评估信号：先验来源，再验可分，最后验自主控制

### 3.1 设备与信号支持先通过，算法不替设备作保证

API到手后的第一步是区分内部测试信号与真实电极输入。检查32路位置映射、缩放、采样率、参考、CAR／DRL和设备滤波；以计数器、validation及接收时间识别缺口。记录原始值与派生值，缩放只做一次。阻抗、平线、饱和、工频占比与头动相关量可用于诊断，但新设备质量阈值要基于实际手册和信号核定，不能套旧五路／至少四路规则。

随后先观察中央区左右任务的频谱／ERD变化、低频启动附近波形和额前／枕区贡献。这些是描述性证据，不能单靠显著图形宣称意图已可解码。若图上差异只来自提示出现、眼睛转动或动作，先标明来源，不能把它包装成纯EEG运动意图。

### 3.2 任务标签与对照必须同时采

| 条件 | 用户做什么 | 回答的问题 |
|---|---|---|
| 左／右手MI | 眼睛居中，仅做动觉想象，身体不动 | 感觉运动节律能否独立支持区分 |
| 脚MI | 指定单脚或双脚，写清任务 | 能否增加一类，不能把脚类改成静息 |
| gaze-only | 不做MI，仅有意左／右注视并保持 | 眼动辅助是否独立有效、能否保持 |
| MI＋同向／反向眼动 | 两信息源一致或冲突 | 分类器主要依赖哪一路、融合是否稳定 |
| 实际动作 | 观察条件，明确不是MI | 是否依赖肌电、感觉反馈或帽体移动 |
| 被动看提示／VR | 看相同画面，不发控制意图 | 是否读到了提示／视觉反馈而不是意图 |
| 自然NC | 无控制要求，允许自然眨眼／观看 | 真实误启动和覆盖，不能只测完美静止 |
| 头动对照 | 小幅自然转头／点头，不要求控制 | 机械干扰与加速度是否成为捷径 |
| 自然前进／转向 | 后续新协议独立任务 | 自然意图能否成立，不从手脚MI换标签得到 |

所有准备段、未标注段保留UNKNOWN。提示时间只能作为任务锚点，实际动作传感器可以作为动作锚点；二者都不能直接称为脑内意图真实起点。3／5／8／12秒保持、保持途中才开始解码、回中与释放分别测试，防止模型只识别一次扫视或提示瞬态。

### 3.3 用有限预算逐步提高证据强度

| 阶段 | 建议安排 | 进入下一阶段的依据 |
|---|---|---|
| P0 输入合同 | API后核对测试信号与真实输入 | 缩放、通道、参考、计数、事件和断流行为已确认 |
| P1 信号可行性 | 两个日期，各约20–25分钟，短block休息 | 出现可重复任务支持；来源对照能解释主要贡献 |
| P2 固定基线 | 补足三个训练日期／佩戴；每类先20次、每次5秒尝试 | 完整组内比较有益，保留无收益结果；不看最终test |
| P3 连续开发 | 另一个开发日期，至少15分钟NC及保持／切换 | 冻结模型、拒识、平滑、事件定义与评价口径 |
| P4 前瞻验收 | 至少三个新日期／佩戴，每次约15分钟NC加任务 | 逐会话完整报告，NC总暴露约45分钟，不把三会话夸成总体高置信 |
| P5 自然意图／速度 | 基线支持成立后另立新任务协议 | 自然方向和速度分别取得新证据；失败保留辅助方案 |

这些是作者建议的实验预算，不是保证足量。疲劳、接触或任务支持不足时，终止当前block并保存原因。两日期的小试只能支持“值得继续／暂不支持”的可行性判断，不足以形成可靠跨日性能结论。完整首轮预计分多日约2–3小时，随休息与失败记录调整，不要求一次长时间佩戴。

### 3.4 高置信来自独立性和反例，不来自随机分窗高分

源SHA、完整录制、日期和佩戴在角色之间隔离。同一连续录制高度重叠窗不跨训练与测试；同库镜像也不跨集合。对CSP、标准化、特征选择、频带／窗长和模型选择采用内层训练组，外层留一个日期。组数不足或某折缺类时，报告“不足以估计”，不能退回随机帧CV冒充。

模型比较采用每类召回、BA、训练／开发差距、含拒识成功率、覆盖、NC误启动、错误动作持续时间与延迟。使用按会话／事件的区间；会话bootstrap只作描述，小样本不会自动标“高置信”。置换检验应在预先定义、可交换的任务block／层内移动整块标签，并对每次置换重复选择和拟合。若block顺序存在固定任务／漂移混杂，不满足交换性就不报告该p值。

建议的统计证据顺序是：外层BA的会话区间→相对合法整块置换的差异→来源负对照→前瞻新佩戴复制→连续NC与保持。若只有平均分高而某日期全失败，不通过。多次探索必须保留搜索范围、失败和候选数，最后独立test只用一次；已查看后便进入历史开发身份。

REST／NC、UNKNOWN、REJECT、INVALID、WARMUP分别记。拒识与预热计入预注册任务总分母，不计有效输出；设备无效时间另报质量覆盖。NC误启动按进入动作事件计数，持续错误移动另列持续时长，不能按网络心跳包数计事件。零误启动也不证明绝无风险：在独立泊松事件近似下，30分钟零事件的95%单侧上界约0.10次／分钟，45分钟约0.067次／分钟；同时报告每会话暴露和事件聚集情况。

## 4. 模型怎么搭：三种信息分支，一套明确的决策语义

### 4.1 第一版模型的确定结构

主参照为：原始输入合同→单向因果SMR滤波→固定历史窗→正则化CSP→分量方差归一化与对数→训练内标准化→收缩LDA→未校准margin。以双频带功率＋线性判别作为对照，确认空间滤波是否真的有增益。候选窗可先固定0.5／1.0／1.5秒，更新间隔建议100ms；这些是实验网格，不是设备参数或500ms首次响应保证。

第一轮先左右手MI，不一次硬做四方向。脚MI和真实NC按支持逐步增加，多类与拒识需要独立模型／数据设计，不能把二类分数补成五类概率。`gnautilus_lab/reference.py`已构建二类数学核心，支持CAR低秩的正则化、固定通道身份和无pickle导出；尚未实现真实训练器、多类模型、概率校准或真实速度解码，这些均在计划中明确后续验收。

候选Riemann协方差基线用于检验不同空间统计假设；EEGNet在数据与跨日支持明确后再比较。JEPA保留为研究候选，以固定预算下相对简单模型的独立增益决定，不恢复旧权重或预先保证大模型改善。[FBCSP原始方法](https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2012.00039/full)、[EEGNet原文](https://arxiv.org/abs/1611.08024)提供方法依据，公开论文分数不转成本设备预期。

### 4.2 自然启动、眼动辅助与持续控制各有边界

低频MRCP分支研究“何时想动”，保留设备可用的低频；不要先套8 Hz高通。代表性MRCP工作存在非因果零相位处理，因此不能把文献动作前约500ms直接当本项目在线提前量。[Lew等原始研究](https://www.frontiersin.org/journals/neuroengineering/articles/10.3389/fneng.2012.00013/full) 需要单向滤波、前缀可见性、误启动与动作代理锚点分别验证。启动可检出也不等于自然方向可解码。

眼动辅助保留极性和低频保持信息。先做方向、扫视起始、保持、回中与自然眨眼区分；不要把EMGEOG演示的绝对值峰触发／扫描游标原样用成方向解码。混合任务须报告EEG-only、gaze-only及融合增量。允许辅助不会取消来源真实性要求。

连续层显式模拟：无控制／候选确认／保持／方向切换／释放／无效停止。只有新的样本支持推进确认；网络重发不算新证据。概率校准须在允许的训练／开发组完成，当前LDA margin不会进入概率阈值门。执行门控不参与方向训练的硬阈值筛样；以后若用联合网络，按真实标签计算监督，不按预测动静截断方向梯度。

速度先用固定安全目标和连续加减速形成顺滑体验。margin、概率、票数或p值不等于“想走多快”。真实速度意图要另行定义任务、监督量、延迟与回归验收；证据不足就保留明确的速度档位／固定速度策略。

### 4.3 哪些Simulink实例被保留，哪些必须改写

| 原实例／模块 | 借鉴内容 | 新实现必须解决的问题 |
|---|---|---|
| MotorImageryBandpower_FES、BCIBatch | 两频带功率、对数特征、WV判别与训练／反馈分开 | 不复制FES；输出为距离；触发支路保存值Gain=0需核实；绑定全部导出参数 |

## 5. MATLAB中间层是否值得做：先作为离线对照，暂不成为生产依赖

| 方案 | 适用情况 | 取舍 |
|---|---|---|
| Python原生数值核心 | 当前默认路线 | 可审查、可做前缀因果与分组测试；需要逐项对齐参考算法 |
| MATLAB Engine离线对照 | 已有合法MATLAB和兼容g.HIsys／g.BSanalyze时 | 在同一固定输入上对比滤波系数／CSP空间／margin；需版本匹配，启动耗时不放每帧 |
| 持久MATLAB进程服务 | 将来确有不可替代模块且获许可时 | 单进程独占状态，设置队列上界、超时和stop；API后再搭，不把每次请求重启引擎当实时 |
| Compiler SDK＋Runtime | 算法兼容编译且允许分发时 | 可以部署函数组件，但MATLAB Runtime不提供交互式MATLAB；厂商许可与依赖另核 |
| Simulink Compiler | 全模型满足rapid accelerator条件时 | P-code／S-Function／外设块不能假定可编译，必须最小模型验证 |
| MATLAB Production Server | 未来确有多用户服务和运维需求时 | 当前单人VR闭环收益有限，不以采购／企业服务替代基础算法验证 |

[Engine官方说明](https://www.mathworks.com/help/matlab/matlab_external/install-the-matlab-engine-for-python.html)要求对应MATLAB环境，最新Engine包不能随意配旧发行版。[Compiler SDK](https://www.mathworks.com/products/matlab-compiler-sdk.html)可部署函数组件；[Simulink Compiler限制](https://www.mathworks.com/help/slcompiler/ug/rapid-accelerator-dependencies.html)依赖rapid accelerator及S-Function支持。因此“能在Simulink打开”并不能证明能打包成无MATLAB服务。厂商P-code／MEX的授权、运行许可、可重分发和版本兼容独立确认。[Production Server](https://www.mathworks.com/products/matlab-production-server.html)是可选部署路线，当前不启动或购买。

## 6. 调试按证据定位，不能靠调阈值掩盖问题

| 症状 | 先查证据 | 处理与回归 |
|---|---|---|
| 波形幅度异常／饱和／平线 | 原始码、单位、增益偏移、输入源与REF | 单位未知即拒绝；修接触或缩放，不能夹幅制造好波形 |
| VR戴上后工频／漂移变重 | 头带压力、线缆、阻抗、无线与原始谱 | 先修机械与参考；保留VR摘戴配对对照 |
| 缺包／重连后乱判 | counter、validation、epoch、缓存支持 | 清滤波／功率／递归／决策历史并预热；配置相同时固定CSP矩阵可保留 |
| 删坏道后维数错 | 模型通道顺序与输入清单 | 停止或用预先训练的匹配模式；不临时压缩／补点 |
| CSP奇异或不稳定 | CAR秩、协方差谱、每折试次数 | 训练内正则化／固定降维；测试集不拟合 |
| 随机分窗高分、跨日差 | source／日期／佩戴、提示和mask-only结果 | 重建分组与负对照，先减少搜索与查标签 |
| 方向只跟眼睛走 | MI-only／gaze-only／冲突 | 若辅助有效如实归类为混合；不能称纯自然意图 |
| NC误动或停得慢 | 进入事件、持续时间、margin语义、窗口和双平滑 | 增加NC支持和拒识；停止优先于平滑，开发冻结后盲测 |
| 更新频繁但主观迟钝 | 窗口、滤波／设备缓存、确认、回执、显示时间 | 分解测量，不能把100ms更新写成100ms首次识别 |
| MATLAB加载／打包失败 | 版本、license、S-Function、外设依赖 | 先最小合法离线复现；不覆盖旧环境，保留Python核心 |
| 公共数据增量不可信 | 镜像、标签、预处理、ME／MI、旧暴露 | 隔离或放弃，保留拒绝原因，不硬凑数据量 |

完整15项“症状→原因→证据→修复→回归”见`protocol_design/failure_matrix.json`。这张矩阵是调试路线，不是本设备已发生故障的记录。

运行方式与接口见项目根`gnautilus_lab/README.md`。当前`python -m gnautilus_lab capabilities`明确返回设备未连接、真实训练／推理服务／VR执行均为false；没有后台进程或网络服务。真实训练检查不能靠更改一个布尔值解锁，必须移植新的治理入口，并在指定物理第二A100上核实运行身份和保存协议／日志；本轮仅CPU合成数值测试。

API提供后按以下顺序接续：

1. 读取API、示例、服务／固件版本与许可，固定独立环境和配置，核对32路映射、单位、REF／GND／Z-channel、采样、计数和aux。

3. 实施新治理协议、原始身份／事件与质量合同，然后开展P1；依据支持决定保留的分支和类别。
4. 按P2／P3建立真实候选和冻结决策，记录分类器原生分数、概率校准与动作映射，不调整现有阈值抬分。
5. 仅监测通过后接入保留中枢。推理和动作独立手动启用，可选校验不决定启动资格；保留采集中暂停执行、失联停止、急停、接收端租约与执行回执。
6. 新佩戴P4验收报告识别、覆盖、误动、开始／保持／停止延迟；VR程序回执与用户眼前画面延迟分别测量，未测显示不冒称已测显示。

这些步骤已经划清可实施边界。本轮的交付是可审阅的迭代方案和受合成测试验证的离线准备组件，不宣称已获得新设备信号、完成高置信识别或实现自然方向控制。


# 补齐API后的采集执行更新

本轮不训练新模型。先在原厂软件完成设备配置并启动允许共享的采集会话，再用独立Windows接收端参与取数；它不修改滤波、不启停原厂采集。数据先在采集电脑追加落盘，再主动TLS送到中枢。中枢按实际通道和采样率显示，原始矩阵不再进入旧七路滤波或旧质量门。

VR和电脑继续主动打标，按住／提示事件直接关联当前stream_id、epoch及已接收样本位置。松开、未标注、断流和失焦不补REST。网络允许下级路由NAT；采集端主动TLS、中枢按签名身份接收Quest HTTP和UDP心跳，UDP向实际源端点回复。

先检查原厂共享权限，再检查设备／列身份、本地写盘、TCP／TLS／身份、中枢持久化、VR回包和标签保存。拔网后本地记录应继续；补传只入库，不刷新实时状态。真实原厂共享、实际32路及参考／地、采样配置、头显运行与校园网仍逐项实机验收。

详见[完整API与独立采集端说明](../integration_20261022/Python%20API与独立采集端接入说明_20261022.md)及[交付验证记录](../integration_20261022/verification/delivery.json)。初期Bandpower／CSP与眼动辅助基线建议保持，但新模板二分类375样本窗和三分类按采样率窗口应在训练前统一，不能盲用旧1.5秒假设。

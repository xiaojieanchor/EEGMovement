# 眼动方向优先：公开数据训练与接入修订

2026-10-24。主路线已改为眼动方向控制，正常手柄操作不要求停止，也不再要求配合四肢想象。原四肢结果留档，45个未开始的四肢任务已取消；切换时已有1个运行任务正常提交产物后结束。

本轮完成20个眼动研究分类器的受治理训练、评估、导出与模型库登记：2个位移对照、9个目标方向首轮模型及9个去基线网络复验。所有20个模型导出前后概率最大差为0，原生类别一致。当前没有自动加载模型，也没有启动推理或动作。

**目前不能声称已有稳定的个人VR控制模型。** 自然头动公开EOG的最佳本轮方案为72.58%分组平衡准确率；高置信接纳部分的总体准确率较高，但包含大量眨眼任务，且垂直方向仍有明显拒识和错误。回中识别与长期保持尤其需要继续改进。

## 1. 当前软件修改

下一次采集模式已设置为gaze_only；未保存配置的新安装也以该模式为默认值。显式保存过的历史paired配置不被静默重写。引导任务返回gaze_navigation_v2身份，仍分别记录导航指令、眼动指令、肢体指令与实验模式。肢体字段NO_CONTROL表示没有肢体任务，不表示没有眼动导航意图。

上看对应前进，下看对应后退，左看对应左转，右看对应右转。该映射用于你本人新采集的指令；公开原生目标角度没有改名为私人导航标签。明确无导航意图的中央注视可标REST；准备、松开、暂停、断流、未知段仍为UNKNOWN。BLINK_TASK与CENTER_RETURN_TASK分别保留，不补成REST。

中枢保留原导航、页面结构和样式。在原训练工作台增加眼动优先说明；导入和采集模式的选项优先显示仅眼动。原模型卡片下拉现在同时显示数据集、seed与模型身份，详情补充分类器接纳覆盖、接纳准确率和原始每类召回，避免只看高分或找不到对应来源。

新增gaze_pipeline：对个人头皮输入明确选择实际存在的前额/额区位置；中央运动区不作为该算法的方向特征。独立EOG研究保留其原生通道。完整32路原始数据仍保存，质量检查没有放松；额区也可能含额肌及电极运动，通道选择不等于已经消除伪迹。其它历史算法继续可选，但不再是本轮默认研究路线。

电脑自主采集和Quest自主采集均消费返回的任务说明及允许标签集合，直接显示向上看/向下看；旧客户端未声明提示支持时，中枢拒绝建立眼动自主采集记录，避免错误标注。组合方向未被当前会话允许时，按钮隐藏且事件发送被拒绝。准备脚本的新研究目录同时绑定计划与准备代码摘要，重跑新代码不覆盖旧质量汇总。

## 3. 标签与时间边界

新目标方向派生使用1.25秒有限历史：指令前0.5秒至指令后0.75秒，320点。输出可见的最晚样本就是窗末；不使用之后的样本、双向网络或filtfilt。源记录开头、阶段长度不够的窗剔除，不补数。首次识别至少涉及任务开始后的0.75秒观测，此试验没有达到小于500ms的首次响应证明；100ms输出合同也不代表100ms首次识别。

以原生目标角度的绝对值至少5度、主轴幅度至少另一轴的1.5倍定义四个原生轴向；对角线、小角度及末250ms类别不稳定的任务窗不进入本轮方向监督。自然头动数据的目标角度会动态变化，不能误要求整段角度完全恒定；只要求输出前最后250ms的原生轴向类别稳定。被排除部分属于本轮标签适用范围之外，不能当作已正确拒识或电气坏样本。

数据1回中阶段固定为CENTER_RETURN_TASK，不能把“从右回中”的向左位移标成向左导航。另两库以原生目标角度流在输出时刻的类别为标签，头姿和目标流不作为模型特征。角度坐标及垂直极性没有完成与本人设备的对应核对，故保留TARGET_H_POS/NEG、TARGET_V_POS/NEG，不直接称为UP/DOWN。目标是提示位置，未独立测得参与者真实眼位。

BLINK_TASK是2秒内要求眨眼的任务阶段，不是逐样本真实眨眼起止。分类该任务阶段的召回不能称为自然眨眼检测灵敏度。所有窗口与标签边界、排除原因、原始源身份保留在gaze-preparation.json所索引的逐源报告中。

## 4. 预处理、分类与选择规则

眼动多层LDA比较三种低频观察：低通形态分支、保留有符号水平的低通分支、0.5-8Hz时域对照。前两者采用4阶12Hz因果低通，初始状态取真实首点的常量稳态，防止DC偏置制造启动尖峰；形态分支减去窗首10%的均值。保留12段有符号均值、相邻变化、峰峰值和导数能量，不仅用平方功率判断方向。水平分支保留输入中已有的慢变化；原厂先前滤掉的低频无法软件恢复。

每一训练折重新拟合标准化及收缩LDA；温度、候选分支/等权组合和拒识阈值只用训练组折外预测选择。实际外层开发记录不传给数值模型拟合。折外分数还参与方案选择，因此是内部选择估计，不伪称另一套独立准确率。个人模型分析通道写入清单，导出后按同一索引取数；不能把手柄活动区域的分类贡献冒称眼动贡献。

原始CNN/GRU使用40轮、seed17；去基线版本使用既有的窗首10%基线减除和0.5-30Hz因果处理，80轮、seed17/29/41。各轮同时保存真实训练与开发指标，按开发组宏平均BA取最佳轮次，平分取最早。网络对照同时改变了处理及预算，不能把全部差值归因于单个滤波操作。网络损失为未加权交叉熵，数据类别并不均衡，是后续需要单独控制的因素。

这些方法借鉴厂商EOG/EMG模板的有符号观察、判别与状态分离思路，保留统一训练、导出和加载接口。Bandpower与CSP继续作为方法对照；仅用对数功率会损失眼动方向极性，不能原样代替眼位/回中判断。[固定头部原始研究](https://doi.org/10.1016/j.bspc.2023.105282)使用联合估计基线与眼位的多模型方法；[自然头动研究](https://doi.org/10.1016/j.bspc.2023.105868)进一步处理眼头协调。本轮没有声称复现其双Kalman滤波、几何模型或VOR模型。

## 8. 实时控制与本人数据到位后的验证

推荐的数据流为：原厂配置/取数 → 时间与通道身份 → 电气/连续性检查 → 前额眼动观察 → 方向/回中/眨眼与拒识 → 中枢状态决策 → Quest票据验证和动作。眼动观察与“当前是否有导航意图”须分开；正常看UI、自然眨眼或转头不能自动当导航。现有手动启动推理、独立允许动作、急停、新鲜度票据、失联停止及采集中暂停动作均保留。

下一阶段需要比较有限窗分类与带基线/眼位状态的因果估计。只识别眼球向左移动，不能证明能识别持续向左看；逐窗减基线可能丢失已保持的偏移。应分别测开始、保持、回中、直接切换、自然眨眼和长时间无控制；状态跨缺包、epoch、模型切换或连接恢复必须清空并预热，不自动恢复动作。该状态估计是后续研究工作，本轮没有伪装成已通过的在线能力。

本人数据采集应按完整会话、日期与重新佩戴分组。建议至少两天、每天两次独立佩戴；先录明确中央无导航、单方向保持、回中、方向切换，再增加自然头动、手柄操作、UI浏览及它们与方向任务交叉的对照。手柄动作应在方向间平衡，避免“某个按钮/手臂姿势=某方向”。单独记录头姿、手柄及提示事件用于审查，不用提示方向作为推理特征。

每次训练前检查真实通道/参考/单位/采样率/原厂滤波、闭合清单、SHA256、标签区间、完整分组和逐类支持；不足则页面明确说明。所有可学习统计和阈值在训练/内层组拟合，保留尚未用于选择的新会话作为后续验收。分别报告原始分类、接受部分准确率、逐类覆盖、正确且接受/完整标签、每分钟误启动、首次响应、切换和停止延迟。采集按钮松开仍为UNKNOWN；回中是否作为明确停止指令，必须在新协议中显式记录，不能通过补标签猜测。

可运行与效果通过分开：满足技术输入合同后可手动试推理，不以某个准确率分数作为启动资格；实际动作依旧受真实输入质量、时效、急停及接收端约束。当前公共EOG分类器均runtime_accepted=false，只可离线加载/回放，不直接用于32路导航。

## 9. 软件验证与证据边界

本轮完成77项Python回归（数据治理、模型导出、接口、前额选择、采集及停止相关路径），四组JavaScript/隔离DOM检查、47项共享C#核心回归，以及真实Unity JsonUtility/UGUI组件的合成检查。新增测试实际经历失败到通过，日志保存在outputs/gaze_priority_20261024/。HTTP实测中枢已连接私有模型服务、眼动模式已保存、11类算法可见，模型通过真实回执登记；未加载模型、推理关闭。

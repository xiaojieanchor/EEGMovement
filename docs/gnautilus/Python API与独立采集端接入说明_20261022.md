# g.Nautilus Python API与独立采集端接入说明

2026年10月22日｜EEGMovement｜补齐材料复核与数据链路实施说明

## 1. 本轮结论：原厂管理设备，独立程序接收共享数据

本项目采用32通道湿电极g.Nautilus，目标仍是在VR中记录运动意图相关EEG、主动标签和视觉反馈。新资料已经提供真正的g.NEEDaccess Python Client API：`pygds 1.20.1`。此前参考的g.Pype是另一套软件，不能以其接口或演示替代本次API分析。

用户已确定：滤波、参考、量程、采样等基础采集设置由原厂软件完成；独立采集程序运行在连接设备的另一台Windows电脑上，读取数据、检查身份、保存并转发给现有中枢。VR和电脑继续主动打标，直接关联实时记录中的样本位置，不要求额外的硬件同步系统。本轮不训练新模型、不恢复旧模型，也不宣称已经取得自然运动意图识别效果。

最重要的接口结论是：**原厂Python高级取数函数不适合直接用于旁听会话**。它会在内部主动执行设备采集启停，并存在双缓冲复用和线程异常传播不足的问题。本项目应依据正式C API建立受控Python/CFFI参与者，从而仅启停本客户端的数据传输。配置权和设备采集权始终属于原厂创建者。[P1，PDF18／印刷14；C1，PDF36–39／印刷29–32；PY，1265–1364行]

另一个前提是原厂会话必须允许共享。C API明确规定，只有原创建者以非独占方式打开同一设备组，后续客户端才能成为参与者。原厂软件使用GDS服务，不等于已经证明它当前允许共享；这一点需要采集电脑上的实际诊断。程序应清楚报告独占、无会话、设备组不匹配等原因，不能静默接管。[C1，PDF10–11／印刷3–4、PDF26–27／印刷19–20]

本说明中的“源码事实”“结构事实”“文档描述”“实现要求”和“待实机验证”分别标注。实现进度和测试结果以同目录集成验证记录为准；材料本身不能证明目标电脑已经采到真实EEG。

## 3. Python、C、MATLAB与Network API的层次

### 3.1 Python封装的是C API，不是独立设备驱动

`pygds.py`依赖numpy、CFFI、pywin32和matplotlib。CFFI从随附头文件理解C数据类型，通过DLL完成实际调用；Windows GDS服务再访问设备。Python包存在并不意味着驱动、服务、设备许可或DLL已经安装成功。[P1，PDF5–6／印刷1–2、PDF9／印刷5；PY，98–119、148–158、191–341行]

文档给出的基础环境是Windows10和Python≥3.6。这是该版手册的描述，不是对任意新Python、numpy、冻结打包器或目标Windows版本的兼容性保证。便携程序需要锁定自身构建环境；采集电脑的原厂DLL、服务与位数须单独检查。目标电脑不必另外安装Python，但原厂驱动与GDS不是便携Python运行时能够替代的。

当前头文件把`GDS_Initialize`和`GDS_Uninitialize`声明为void。`pygds.Initialize()`的True是Python包装层成功返回值，不能误当C函数返回的GDS_RESULT。源码`_chk`先判断返回值是否为空，因此仅凭331行外层`_chk(...)`不能认定该封装存在void返回错误。[H0，315–330行；PY，171–173、331–341行]

### 3.2 四种接口可交叉验证，不能机械混用对象名

| 层次 | 主要职责 | 可借鉴内容 | 本项目取舍 |
|---|---|---|---|
| Python pygds | 设备对象、配置包装、numpy矩阵和演示 | 字段别名、设备能力查询、缓冲和数据排列 | 深入理解其行为，旁听采用受控底层调用 |
| C Client API | GDS句柄、配置结构、回调、数据读取、资源释放 | 创建者／参与者权限、类型与返回码的正式依据 | 作为CFFI接口契约 |
| MATLAB API | gtecDeviceInterface与设备配置对象 | single矩阵、GetData的scans×channels语义、批量取数建议 | 补充核对，不启动MATLAB或恢复旧模型 |
| Network API | GDS内部消息、控制／数据流、错误码、事件 | 说明SDK如何组织会话、缓冲与命令 | 解释底层；本项目不在校园网直接重写或暴露GDS协议 |

MATLAB的`GetData`返回`scans_received`和single矩阵；0或空参数可以读取当前可用扫描，文档建议使用推荐NumberOfScans或其倍数避免丢失。其`StopDataAcquisition`描述同时涉及停止和关闭，不能直接当参与者的StopStreaming使用。[M1，PDF20–21；C1，PDF38–43／印刷31–36]

Network API区分控制应答和数据传输，并有独立的缓冲错误码。直接透传这一协议会把原厂服务端口、会话控制和客户端回连关系带到校园网络；本项目只在采集电脑loopback访问GDS，跨机使用自己的受限TLS数据协议。[N1，PDF14–15、21–23、46–48]

## 4. 连接生命周期与权限：谁能做什么

### 4.1 原厂DAQ会话以完整设备列表识别

一个DAQ单元可以包含一个设备，或同型号且硬件同步的一组设备。创建者首次打开这个设备组，参与者必须使用**相同顺序和内容**的设备名列表加入。相同USB电脑上能看到两个设备，不意味着它们已经同步；不能随意合成同一个数据组。[C1，PDF10–11／印刷3–4、PDF26／印刷19；H0，352–377行]

| 行为 | 创建者 | 参与者 | 本项目允许 |
|---|---|---|---|
| 读取当前配置、能力和数据组织 | 可以 | 可以 | 可以，写入会话描述 |
| SetConfiguration | 可以 | 不允许 | 不调用 |
| StartAcquisition／StopAcquisition | 可以 | 不允许 | 不调用 |
| StartStreaming／StopStreaming | 可以 | 可以，仅影响自身连接 | 可以 |
| GetData | 自身streaming已开且设备已采集 | 同左 | 可以 |
| BecomeCreator | 特定异常恢复场景 | 有条件提升 | 不调用、不自动接管 |
| Disconnect | 销毁自己创建的DAQ，会影响参与者 | 仅离开自身连接 | 完成清理后调用 |

程序发现原厂会话尚未开始时保持等待；若原厂独占，报告访问拒绝。即使检查后发生竞争，最终`isCreator`若为真，也必须立即释放新创建的空会话，不配置、不开始设备采集。[H0，352–405、419–494行]

### 4.2 正常参与流程

![参与者取数流程](integration_20261022/figures/participant_flow.png)

程序先核对原厂SDK文件、进程位数和本地服务，再枚举设备，确定实际序列号及共享组。以非独占标志加入，并核对返回身份。之后读取配置、可用通道、数据宽度、滤波列表和缩放，只开启自己的streaming。每次GetData后立即复制有效行，提交本地记录，再由独立网络工作线程发送。

正常退出按“停止自身streaming→注销本连接回调→释放配置／枚举列表→Disconnect→在库生命周期结束前Uninitialize”的方向清理。具体返回码和已完成步骤决定哪些资源需要释放；不能在DLL卸载或静态析构中才等待Disconnect。[C1，PDF28／印刷21；H0，379–393行]

### 4.3 不能把import当作没有副作用的文件读取

`pygds.Initialize()`会检查GDS服务；服务运行时倾向加载GDSClientAPI.dll，未运行时转向GDSServer.dll，并调用GDS_Initialize。模块还会自动初始化。因此材料分析只读取wheel中的文本，不import它。独立程序显式控制SDK加载阶段、绝对路径和DLL搜索目录，避免加载错误版本或无意启用另一种服务模式。[PY，113–119、191–223、267–341、367–374行]

演示中的SERVER_PORT为50223、CLIENT_PORT为50224。本项目自己的参与客户端应请求可用本地端口，避免和原厂软件争用固定50224；跨电脑的数据接收端口8767属于项目协议，两者不是同一端口或同一个服务。

## 5. 一行数据究竟代表什么

### 5.1 scan、sample、column必须分清

C API把一组同时采样的全部输出列称为scan。若有C列、N个scan，返回float32数组的形状是N×C，第s行第c列位于`buffer[s*C+c]`。GetDataInfo返回每设备的输出列数和所需元素数，缓冲容量按float元素而不是字节传入。实际返回scanCount可能少于请求数。[C1，PDF40–43／印刷33–36；H0，510–549行]

EEG通道的返回单位为µV，附加通道有各自物理意义，不能全部乘同一个“µV换算系数”。原厂缩放Factor／Offset是需要记录的配置身份，不能因为存在这两个数组就对已由API返回的数据再做一次缩放。保留API返回的原始float32数值，派生处理另作版本。[C1，PDF42、93／印刷35、86；PY，1571–1610行]

### 5.2 g.Nautilus的输出列随启用项变化

| 先后顺序 | 列组 | 数量与单位 | 解释与验证 |
|---|---|---|---|
| 1 | 已启用EEG模拟通道 | 实际启用数量；µV | 以物理通道编号关联，不能压缩后丢失原身份 |
| 2 | AccelerationData | 3列；g | x/y/z，文档量程±6g；不当EEG输入 |
| 3 | Counter | 1列；样本计数 | 是设备样本身份线索，不是UTC或VR时钟 |
| 4 | LinkQualityInformation | 1列；百分比 | 无线质量，不是电极阻抗 |
| 5 | BatteryLevel | 1列；百分比 | 电池状态，不代表数据有效性 |
| 6 | DigitalIOs | 1列；位编码 | 同步数字输入，不能把整列当作第33路EEG |
| 7 | ValidationIndicator | 1列；0或1 | 成功无线传输的标识，不等于皮肤接触良好 |

32 EEG加全部上述附加项时，理论输出宽度为41列；实际必须由配置和GetDataInfo共同确认。若没有加速度，后面的Counter等列会提前，不能固定取第36列之类。缺失的Counter／Validation应登记为未启用，不能用软件递增序号伪造硬件计数或填充“全有效”。[C1，PDF94–95／印刷87–88；HN，142–224行]

官方`IndexAfter()`给出的名称定位可用来理解顺序，但源码在g.Nautilus分支通过可用性累加EEG通道，没有在这段循环逐项过滤Enabled。因此在部分通道关闭时不能盲信`N_ch_calc()`。受控接收端应依据实际启用列表计算、再和GetDataInfo比较；不一致就停止该数据配置的实时接收，而不是截掉多余列让形状通过。[PY，1102–1122、1188–1234行]

### 5.3 设备位置、显示名称和输出列是三个身份

API中的通道1不是默认Fp1，Counter所在列也不是一个电极。设备提供的通道名可以记录，但可调整电极位置最终需要实际帽型、插线表和佩戴记录确认。候选32点位只是研究建议，不能自动写入`layout_verified=true`。

描述至少保存序列号、输入源、启用通道物理号、输出列顺序、采样率、参考／地说明、CAR与NoiseReduction、BipolarChannel、Sensitivity、每路滤波索引及其查询定义、缩放、设备／SDK文件身份。未核实的参考、地或佩戴编号保留未知。配置改变后必须开启新的流或epoch，禁止让一个数组列在原流中悄悄变成另一种信号。

## 6. 取数、缓冲与延迟的真实行为

### 6.1 GetData的请求量不等于硬件打包量

SamplingRate决定每秒扫描数；NumberOfScans是原厂设备或服务的推荐取数批量；GetData传入的scanCount是本客户端希望读到的扫描数。三个概念不能混为一谈。C API提醒，在网络／loopback调用下，过小的固定请求可能因往返开销无法实时取完，造成延迟或缓冲溢出。[H0，528–545行]

文档与头文件还存在一个需记录的差异：C API手册配置表写250Hz→8、512Hz→15，而gNautilus头文件注释写250Hz→8、500Hz→15。程序不能依据目录名或注释强行把设备改成500或512；查询实际支持列表，并记录当前配置。本轮也不修改NumberOfScans。[C1，PDF94／印刷87；HN，156–165行]

### 6.2 高级Python取数有双缓冲与隐含启停

`GetData(scanCount, more)`创建取数线程和两个float32矩阵，线程填一个矩阵，当前线程处理另一个，再交换。回调想长期保留数组，必须copy；把原数组对象直接交给异步发送或稍后写盘，后续交换可能覆盖其内容。[PY，1265–1329行；P1，PDF18／印刷14]

底层`_getdata()`会先调用StartAcquisition和StartStreaming，最后StopStreaming和StopAcquisition。它的异常处理使用宽泛except后pass，调用线程通过队列等待结果时可能收不到错误，退出的join也可能等待。因此不能只在外面包try/except就假定获得了可控的异常边界。本项目将SDK置于独立进程，监督进程检查数据进度和退出时间；工作进程卡住时可以有界结束自身进程，原厂创建者仍独立运行。[PY，1331–1364行]

### 6.3 延迟分项记录，不把到达时间冒充采样时间

| 分项 | 可直接记录什么 | 不能由此直接得到什么 |
|---|---|---|
| 设备采样与无线缓存 | 硬件Counter、Validation、批量长度 | 每个ADC样本的UTC时间 |
| SDK读数 | 取数调用前后单调时钟、返回行数 | 精确的射频传输单向延迟 |
| 本地排队与落盘 | 队列长度、提交耗时、持久化序号 | 对端已经持久化 |
| 网络 | 发送／收到／应答、往返时间、积压 | 未校准三端时钟的单向差值 |
| 中枢事件 | 标签发送时间、收到时间、当前样本位置 | 人的意图真实发生时刻 |
| VR | 指令／按键阶段、帧号、回执 | 光子实际到达眼睛的硬件时刻 |

本项目按用户要求延续主动打标。网络时刻和样本索引足以让记录可追溯，但不把它包装成硬件同步或反应时生理测量。人的反应差异、指令保持阶段、准备阶段和链路延迟是不同来源，原记录保留这些字段，后续实验可按任务定义选择对齐方式。

## 7. 质量、阻抗与事件标记各自回答不同问题

### 7.1 Validation=1不代表电极接触合格

ValidationIndicator描述无线传输有效性；Counter帮助识别连续性；LinkQuality给出无线状况；Battery描述供电。它们都不能代替阻抗、饱和、非有限值或实际信号噪声检查。状态界面应分别呈现“收到数据”“设备标识有效”“连续”“接触未测量”，不把一个绿色灯复用到所有层次。

g.Recorder手册PDF68–70给出了g.Nautilus设置入口及上述附加通道的配置方法。现场建议启用Counter和Validation，并保留配置快照；这是原厂软件中的操作，不是由本程序写入参数。若未启用，程序仍可保存带缺失说明的诊断记录，但不能伪造完整设备连续性或电气QC凭据。[R1]

### 7.2 阻抗函数不是无条件安全的在线状态读取

Python封装文档在GetImpedance处提到特定旧布局的electrode15=Cz，C头文件提到参考Cz异常会使测量失败。两者不能据此推导当前32点布局的第15路必须接地，也不能把示例接线说明覆盖实际帽型手册。阻抗测量会涉及设备测量模式和条件，独立参与者不在实时数据流中擅自调用；由原厂操作与实际电极型号确认。[PY，1517–1569行；HN，450–464行]

### 7.3 软件主动标签和数字触发都保留原身份

DigitalIOs中的事件位来自硬件输入。VR／电脑主动标记来自用户界面和软件事件。二者可以在同一个会话中保存，但字段必须说明来源。软件标签不会自动写入g.Nautilus数字输入，也不会成为原厂采集软件的硬件触发。没有触发附件时，保留软件事件关联已满足本轮需求。

## 8. 补齐模板后，哪些算法认识需要更新

### 8.1 M147普通Bandpower是四个频带特征加线性判别

结构为采集→四个Bandpower引用→log10→四维加权和加偏置→反馈缩放与范式／记录。四个实例的具体频带和窗口见参数表；这些值保存在Reference块的InstanceData中，不能只读顶层Block/P。WV由工作区提供，PreLoadFcn在缺失时仅创建零向量，不表示已经得到训练过的分类器。[E2，M147；PY类比只解释API，不是此模板实现]

| M147实例SID | 频带 | 保存阶数 | 功率窗口 |
|---|---|---|---|
| 40、41 | 8–12Hz | 4 | MultiDeviceDAQ_getSampleRate样本 |
| 42、43 | 16–24Hz | 4 | MultiDeviceDAQ_getSampleRate样本 |

两路相同频带并不表示输入是相同电极，需结合采集块选择和接线核对。数字8–12与16–24是此模板的保存值，仍需为当前用户重新选择／验证；不把它称为当前设备已经配置的频带。

数学上可用因果带通后的滑动均方近似其特征形式：P_k(t)=窗口内y_k²的平均，f_k=log10(P_k)，d=b+Σw_kf_k。这里的公式是模型与库结构的解释，数值等价仍需对原厂S-Function验证；不能把d当校准概率或行走速度。新程序本轮保存原厂输出的数据，不再次应用这些模板滤波。

### 8.2 二分类CSP在线模板与三分类模板的窗口并不相同

| 模板 | 空间分量 | 方差窗口 | 对数与归一化 | 关键限制 |
|---|---|---|---|---|
| M149 TwoClass | W_CSP首2、末2行，共4分量 | 每个Variance实例375样本 | 4分量归一化后log10，再Apply Classifier | 若实际250Hz则1.5秒，512Hz则约0.732秒；不能固定称1.5秒 |
| M148 ThreeClass | leftAll、rightAll、footAll各首2末2，共12分量 | WindowLength=实际采样率 | 12维方差归一化后log10 | 这里对应约1秒；LEFT／RIGHT／FOOT没有REST |
| M147 Bandpower | 四个实例 | WindowLength=实际采样率 | 每路log10，WV线性加权 | 默认范式no feedback，不能当已训练闭环 |

二分类增益矩阵在SID746；三分类空间矩阵在SID938–957。三分类不是把二分类输出直接改成三个方向，而是显式持有三组空间投影和12维输入。Apply Classifier引用块的分类器参数有bdmxdata UserData引用；仅看到外部引用时不能推断具体训练权重、拒识阈值或概率校准。[E2，M148、M149]

二分类模板带通保存值为8–30Hz，三分类为5–30Hz，LPOrder与HPOrder均为5，SampFreq均引用实际采样率。它们是所给模板的不同设置，不能笼统归纳成所有CSP都使用同一8–30Hz滤波。

方差归一化子系统还包含常数4或12，需按连线核对其缩放位置。不同实现若只差特征上的常数平移，可以由重新训练的线性偏置吸收，但不能保留旧分类器权重并任意改数学表达式。迁移应保存实际公式和权重的联合身份，而不是只复制一个W_CSP矩阵。

### 8.3 新MAT文件消除了部分依赖缺口，但没有证明交叉验证无泄漏

30通道Nautilus蒙太奇实际为Fz、FT7、FC5、FC3、FC1、FCz、FC2、FC4、FC6、FT8、T7、C5、C3、C1、Cz、C2、C4、C6、T8、TP7、CP5、CP3、CP1、CPz、CP2、CP4、CP6、TP8、Pz、POz。它是30个EEG位置，不能自动用于当前可调整的32路帽。[E3]

四份classrun_3class矩阵各为3×45，每类15试次；这是示例标签组织证据，不是当前用户的试次标签。artifactDetection与plotOnly4CSPs的文件虽已找到，但内部选择逻辑仍不可读。对原示例CV的限制仍成立：需要确认CSP、标准化、时间点、阈值及特征选择是否在正确的训练折内，不能因文件补齐就宣称该问题已消除。

### 8.4 新基础库更值得借鉴的是职责分离

| 新证据 | 可见能力 | 值得迁移的逻辑 | 不直接照搬的内容 |
|---|---|---|---|
| M097 Preprocessing | 滑动均方、移动平均、滤波、源导联 | 每步有明确状态与窗口 | 保存的256Hz、250Hz和示例频带混杂，不能直接套当前设备 |
| M100 SignalQuality | 标准差、幅值上下限和显示更新 | 数据检查与显示分离，原状态带时间范围 | 默认阈值与单位枚举尚需运行／手册匹配，不继承旧质量门 |
| M111 Transformation | 通道选择、事件选择、触发窗、预触发、基线修正、帧替换 | 事件身份与样本区间明确，坏段保留原因 | 用NaN替换或裁窗不能让无效段变成REST／训练有效段 |
| M087 LSL | 发送／接收名、类型、采样率参数 | 流描述中保留通道、来源和采样信息 | 示例128路4800Hz与本设备无关；发现与网络路由要实测 |
| M114 UDPInterface | sender编码和receiver丢迟到包选项 | 实时处理应拒绝迟到数据 | 示例端口与IP无身份验证，不能直接用于校园网络动作 |
| M140／M141混合BCI | Minimum Energy、Apply Classifier、median、P300流程 | 不同信号／刺激的控制权和模式切换分开 | 刺激、训练和动作回路不能默认为自然意图识别 |

这些库为以后算法迁移提供更完整的实现参照。本轮完成数据契约和记录链路后，仍应先用明确的频带功率／CSP线性基线建立新设备的独立会话成绩，再比较复杂模型。JEPA仍是候选路线，材料补齐不能自动证明其优于基线。

## 9. 独立程序、中枢和网络的职责

![跨电脑接收与主动打标](integration_20261022/figures/network_dataflow.png)

### 9.1 采集电脑保持原厂所有权

独立程序仅参与原厂共享会话。开始接收会创建本地原始日志并主动连接中枢；结束保存只关闭自身数据流和文件，不停止原厂采集。界面应能分辨“原厂未采集”“已参与但未收到数据”“本地已写盘”“中枢未连接”“中枢已持久化”，避免把一个网络连接状态当整链成功。

程序冻结自身运行环境为Windows x64便携目录。SDK DLL和头文件来自目标电脑已安装的原厂目录，不借冻结打包自动替换驱动、服务或许可证。运行前检查绝对DLL路径、位数、服务和实际设备配置；本机没有设备时只可执行模拟／软件测试，不能显示真实采集已通过。

### 9.2 TLS连接由采集端发起，NAT不要求反向进入采集电脑

默认中枢TLS端口8767。采集端持有配对身份和固定服务端证书指纹，主动发起连接；双方验证协议版本、挑战和身份后交换描述和数据。帧由长度、JSON头和float32体组成，有最大长度、行列数、序号和流身份检查。原始EEG不通过未认证广播传送。

下级路由器若工作在NAT模式，采集端向外连接可沿已有映射返回；VR的主动HTTP与UDP心跳亦以认证身份处理，UDP回包发往观察到的来源端点。配对不能继续依赖“内网地址必须等于登记IP”，也不能因多个终端共用一个路由外网地址而混淆身份。映射变化应结束旧执行租约并重新握手，原有接收端时效票据不放宽。

“接在同一个校园网”不等于必然互通。校园网ACL、终端隔离、Windows防火墙和路由策略都可能阻止连接。诊断先验证采集端到中枢8767，再验证VR管理和UDP回包；不可达时现场把三端接到同一路由或AP，或者由网络管理员处理隔离策略。本程序不自行扫描校园网，也不要求暴露远端管理入口。

### 9.3 实时与补传具有不同资格

块包含stream_id、epoch、seq、sample_start、sample_count、源端读数时刻、接收时刻和数据哈希／提交身份。源端与中枢的单调时钟起点不同，不能直接相减计算单向延迟。只有当前实时连接上的新鲜live块更新实时缓存；历史backfill只补存储，不刷新source_fresh，不授予模型或动作资格。

重连时以持久化序号去重。已经落盘的块不能因为重复发送被计成两次EEG；相同序号内容不同则拒绝并记录冲突。设备重新开始、配置改变或计数异常造成的断点都要显式记录，不能只把本地sample_start继续递增而伪装设备连续。

## 10. 主动标签与原始记录的关联

### 10.1 一个标签事件保留四类信息

| 字段组 | 内容 | 意义 |
|---|---|---|
| 任务身份 | session_id、范式、试次、phase、label、build_id | 说明用户被要求做什么，不宣称真实意图已被测量 |
| 发送身份 | 设备／页面、事件seq、发送时间、帧号、输入来源 | 重试幂等，区分VR射线、桌面输入和验证工具 |
| EEG锚点 | stream_id、epoch、sample_index_end、数据是否新鲜 | 指向当时中枢实际接收支持范围 |
| 接收与状态 | 中枢接收时间、确认序号、暂停／失联／退出原因 | 区分事件已发送、已收到和已保存 |

按住开始是一个标签区间的起点，松开结束后恢复UNKNOWN，不自动补REST。提示任务的prepare、cue、task、rest各阶段按既有协议保存。标签是主动任务或用户报告信息，不能把它当作当前新模型的预测正确证据，也不能将按键造成的肌电混入后再宣称纯脑意图识别。

### 10.2 数据中断时标签也必须停止延伸

设备数据变旧、流身份改变、发送者失联或页面退出时，当前标签区间以原因结束，后续样本进入未标注状态。重连不会把上一条hold_start跨过缺口自动延长。任务阶段与事件序列不合法时返回错误；相同事件的重试内容必须一致。

本轮沿用已有的主动打标逻辑与软件时钟信息，不要求额外的光电或数字触发硬件。若未来研究需要精确视觉刺激潜伏期，可以增设硬件验证，但不改变已保存的软件事件原身份。

## 11. 原始文件、恢复与检查点

### 11.1 双端记录的用途不同但身份一致

采集端本地日志保证网络断开时原始数据仍可保存；中枢记录用于与VR／电脑标签、会话和状态合并。两端都保存相同描述和块身份，比较样本数、序号、哈希及缺口，不以“网络发送成功”代替“对端持久化成功”。

追加原始float32文件配合逐块提交日志；先写数据并同步落盘，再提交块索引，最后才返回durable确认。崩溃恢复只保留完整提交块，未提交尾部可隔离／截除；已经提交但哈希不匹配的内容必须报错，不能当成普通断网缺块。关闭时生成原子清单，保存计数、哈希、异常摘要、通道配置和软件版本。

本地磁盘故障与网络故障采取不同处理：网络断开时继续本地记录；磁盘满或写盘失败时停止自身接收，通知中枢并保留错误，不能悄悄丢弃队列、继续显示正在可靠记录。原厂设备采集不由该程序停止。

### 11.2 中枢检查点必须分别显示

| 检查点 | 成功条件 | 失败或未知的表现 |
|---|---|---|
| SDK文件与位数 | 目标SDK身份可读，位数相容 | 缺失DLL／头文件／依赖，禁止伪装设备存在 |
| 原厂服务 | 本机GDS可访问 | 提示服务不可用，不自动安装或切换独立服务模式 |
| 共享参与 | 非独占原厂会话，返回参与者身份 | 无会话、独占、设备组不符分别解释 |
| 描述匹配 | 当前配置、列数与GetDataInfo一致 | 配置不符停止该流，不能截列凑32 |
| 实际取数 | 正确形状和新鲜返回行 | 无数据、非有限值、设备无效各自保存原因 |
| 连续性 | 硬件计数与原始序号可审计 | 缺失或未启用不冒称完整连续 |
| 本地存储 | 提交成功、剩余空间足够 | 写盘失败停止接收并报错 |
| 网络身份 | TLS证书、配对和协议一致 | 地址可达但认证失败仍显示失败 |
| 中枢存储 | durable确认及块索引一致 | received与durable分开显示 |
| 主动打标 | 会话和事件合法，已保存确认 | 不沿用已结束或过期会话 |
| VR执行 | 票据、连接和停止机制有效 | 数据或链路变旧即停止；本轮无新模型输出 |

## 12. 软件验证与实机验收分别进行

材料静态分析能确认源码、参数、结构和文档约定；模拟SDK测试能确认参与者路径、异常、数据协议及恢复逻辑；本机网络联调能确认TLS、重连、存储和标签关联。三者都不能证明g.Nautilus实际采样质量、原厂共享能力或现场校园网络已经合格。

| 场景 | 软件验证应覆盖 | 目标电脑仍需确认 |
|---|---|---|
| 会话权限 | 无会话、独占、参与者、意外创建者立即释放 | 实际原厂软件如何提供共享会话 |
| 数据组织 | 32 EEG＋不同附加列、部分读取、宽度不符、配置改变 | 实际列顺序、硬件版本、采样率和量程 |
| 故障 | SDK异常／卡住、队列满、磁盘失败、掉线 | USB／无线／服务异常时原厂返回的具体错误 |
| 网络 | 错证书、错配对、重复块、补传不刷新实时、NAT身份 | 8767／VR端口可达性和路由映射 |
| 打标 | 提示、保持、松开、暂停退出、重试幂等、跨epoch | 实际头显／电脑操作体验与保存的标签区间 |
| 存储 | 完整块恢复、提交损坏拒绝、两端数量和哈希 | 长时真实记录及断电／断网恢复 |
| 控制 | STOP、急停、断流与失联停止回归 | 现场接收端回执；不表示新模型已通过 |

首个实机会话应先做不带动作的短录制，核对原厂显示与两端记录，再做主动打标和一次计划内断网。完成配置、信号、存储和标签核查后，才能进入数据采集阶段。新模型、跨会话准确率、自然意图和速度解码保留为之后独立验证的任务。

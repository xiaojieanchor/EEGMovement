# 热点高频暂停软件复核（1.1.15）

## 结论与证据范围

1.1.14 实机仍出现过高频暂停，本报告不把上一轮发布当作问题已完全解决。本轮按用户要求，在脑电采集电脑关闭后，使用隔离实例完成设备之外的验证，不访问原厂 SDK、不向生产中枢注入模拟 EEG、不启动训练或实际 VR 动作。

补充确认并修复两条程序路径：

- **历史描述污染实时输入**：热点补传连接仅提交旧流描述，就会调用实时描述回调、替换输入合同并清空窗口。新增回归先复现此失败。现在握手只建立日志，只有通过新鲜度检查的实时块才能提交运行合同。
- **热点目标被自动发现覆盖**：明确填写 `192.168.137.1:8768` 时，建配置及重连发现仍可能选择 `198.18.0.1` 之类 VPN 接口。现在显式目标具有优先权；状态、数据和探测重连均不替换地址。热点 HTTP／WebSocket 显式直连，不使用系统 HTTP 代理；有意选择公网模式仍使用原代理策略。

这些问题均有代码和隔离失败测试支持，但尚不能断言它们解释了全部实机暂停。最后现场采集端回传一度已过期，不能据旧状态断言用户本地已经停止取数。

## 数据、模式与诊断

保留 250ms 实时边界、历史补传隔离、固定 8768、版本化通道及原厂参与者权限。断流保持已开启模式，关闭旧标签区间并等待恢复；UNKNOWN 不补成 REST。恢复前后清除旧推理证据，VR 动作需要重新允许。

`gnautilus.lan_listener` 新增：

- `failures`：最近 8 次连接异常及发生阶段，避免异常被静默吞掉。
- `block_stats`：收到、重复、实时接受／拒绝、票据缺失或不合理计数。
- `timing`：块号、实时／补传标记、客户端年龄、票据经过时间、估计年龄、入库耗时及实时接受结果。

不以节流日志或放宽阈值替代修复。计算连接相关回归同时验证原服务身份、超时释放和手动断开不被迟到回复撤销；网页不把缓存模型或离线分类器冒称可实时启动。原页面结构保持。

## 当前使用方式

采集端与VR端按软件类型自动归属。本项目同时最多一个EEG采集端和一个Quest；首次联网时应用自行领取并私有保存身份，用户不需要公网配对文件、连接码或中枢人工批准。首次领取需要本机中枢在线、记录关闭且动作停止；已有同类设备在线则等待其断开。内部身份用于重连、签名、去重和更新回报，由应用管理。

采集电脑安装[Windows 1.1.2安装器](../../../outputs/relay_20261023/release/EEGMovement-Setup-1.1.2.exe)后运行工作台即可。1.1.2自动迁移旧版仅存配对路径的设置，设备序列号和保存目录保持；只有用户明确选择局域网兼容才保留外部路径。需要切回时仍可点击“恢复公网自动连接”，无需文件。默认公网入口为`106.55.251.83:443`，仍完整验证专用CA、证书有效期与IP身份。自动连接不依赖内网广播、固定内网IP或校园网入站端口。

本机访问[原中枢工作台](http://127.0.0.1:8765/)；`/gnautilus`也返回该工作台。保持原导航、侧栏、卡片、模型页面与动画，只在原位置更新设备、实际通道、模型和公网状态。

## 自动连接实现

| 环节 | 实现与可核查来源 |
|---|---|
| 软件角色 | Windows固定`eeg`，Quest固定`quest`；云端每种角色最多一个活动设备，允许同一身份／启动代次的独立数据、控制、补传和预览通道 |
| 首次身份 | 客户端本地产生RSA3072密钥；本机中枢把角色身份用AES-GCM封装，再用RSA-OAEP交给请求客户端；云端仅保存密文及请求索引 |
| 身份持久化 | Windows保存在应用数据目录，Quest保存在Android私有目录；升级保留应用数据；公开安装包不含设备秘密 |
| Windows交互 | 后台等待、取消与重试，不阻塞波形、保存和日志；端到端连接测试必须获得当前中枢签名回包 |
| Quest交互 | 自动领取→公网认证→中枢回包；状态、事件、更新与控制保持原接口语义 |
| 权限边界 | 公网只路由固定设备消息，不能访问任意内网URL、端口或执行命令；内网模型访问仍只在本机模块内 |

主要源码：`eeg_relay/onboarding.py`、`server.py`、`enrollment_client.py`，`hub/public_relay.py`，`gnautilus_acquisition/qt_gui.py`，`EnrollmentBridge.java`与`QuestNetwork.cs`。旧局域网兼容入口保留，但不作为公网必需步骤。

## 本轮修复的连接问题

- Quest周期性请求`/v1/calibration/status`曾被公网白名单拒绝，导致整个中枢通道断开。现明确返回新设备“未配置”状态；合法但不支持的操作单独返回错误，不切断全部数据链。
- 中枢重启后，Quest仍会发送旧中枢会话的ACK。现先识别旧会话并重新握手，不提交旧ACK、不执行动作；当前会话的ACK递增、租约和签名检查保持。
- 异常VR报文按消息计数并拒绝，不拖断EEG通道。
- Windows Python直接TLS服务在本机测试中存在TLS1.3票据相关握手停顿。纯WebSocket复现后，仅关闭该直接服务的TLS会话票据；TLS1.3和完整证书校验保留。公网Nginx原已关闭票据。诊断记录保留默认设置失败与修改后300次连续成功的对照。
- 中枢身份请求禁止重定向，修正了urllib处理器优先级并以重定向回归验证，避免把认证头发送到跳转地址。
- Windows1.1.1初次安装默认为自动连接，但旧版用户设置若残留局域网路径仍会沿用。1.1.2增加明确的连接模式并自动迁移未声明模式的旧设置；设备和保存路径不变。先以测试复现，再验证迁移与明确局域网选择的重启保持。

## 更新与现场检查

安装包、便携包和APK均按不可变版本名发布，先核对云端SHA256，再原子切换离线签名清单。旧发布保留，不以相同版本覆盖不同内容。Windows原生安装和失败恢复在隔离本机目录核查；Quest2.1.2已在所连头显实际安装运行。当前Windows1.1.2的发布与安装身份以[publication.json](publication.json)、[release.json](release.json)和[windows-install-check.json](windows-install-check.json)为准，签名清单及HTTPS范围下载核对见[update-download-check.json](update-download-check.json)。

Windows冻结构建与源文件核对见[windows-build.json](windows-build.json)和[windows-source-check.json](windows-source-check.json)。1.1.1冻结后的服务端专用修改另外保留历史证据，1.1.2重新冻结当前源码。Quest构建[android-build.json](android-build.json)记录源快照稳定、实际APK哈希和原签名证书，未导出签名私钥。

配套[增量源码ZIP](../../../outputs/relay_20261023/release/EEGMovement-Relay-Source-1.1.2-Quest-2.1.2.zip)包含当前Hub、采集、传输、Android桥接、发布与核查源码，不含Unity完整资源、原厂SDK、运行数据和私钥。[包内容核查](package-secret-check.json)以本机实际设备秘密值检查Windows ZIP、APK及源码ZIP；仅记录是否命中，不输出秘密值。原始界面脚本回归见[frontend-workbench.log](frontend-workbench.log)、[frontend-active-label.log](frontend-active-label.log)，现行页面启动检查见[frontend-boot.log](frontend-boot.log)。

现场依次检查：中枢公网在线→客户端自动角色连接→签名中枢回包→原厂共享会话→实际采样与列宽→本地落盘→云端落盘→中枢落盘→事件与样本关联。设备有效性不代表接触质量，云端保存不代表中枢保存。另一台采集电脑、原厂共享会话、真实EEG和任务标签同步仍待现场确认。

网络恢复、连接代次改变和中枢重启后动作保持停止；无控制、未标记、断点和无法定位的事件不补成REST。公网转发不提供内网代理，新模型尚未配置，本轮未启动训练。

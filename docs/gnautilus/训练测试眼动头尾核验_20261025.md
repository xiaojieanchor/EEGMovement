# 眼动头尾、预热与训练／测试支持核验

2026年10月25日。本轮逐样本溯源、冻结模型回放和标记，不重新训练，不修改原数据与试次划分。

## 核验结论

**你的担心部分成立：旧图把未标注和未预热画成同一种颜色，而且上轮新增额部分类器确实使用了过短的试次前置上下文。** 方向试次原先只有约1秒前置信号，模型需要1.5秒实际输入预热，造成训练读出和按试次测试的前约0.5秒任务无法有效评分。旧图尾部约1秒灰色通常是任务标签UNKNOWN，信号仍在模型里处理，并非统一停止推理。

**实际连续JEPA训练与上轮新增额部轻量分类器必须分开。** 前者已经扩展并合并了同源连续训练支持，多数方向任务的起始眼动没有被预热挡住；后者当时按旧试次重新预热，方向任务最初约0.5秒未进入有效训练输出。原始样本未删除，但“保存”“模型读到”“直接监督”并不等价。

已从本机对应原始流恢复更长真实上下文，并把训练／验证／测试共15个完整试次另存为内部审阅修正版。原片段与原始流逐值匹配，新增上下文保持UNKNOWN，原有标签逐样本保留。还保留角色隔离视图和连续流诊断视图，不为了消除预热而把不同角色偷偷混作独立测试。

**目前不能确认眼动分类头已能正常识别所有方向或持续眼位。** 补足真实历史后，连续诊断中的测试任务有效更新由662／695增加到695／695，但右向、后向仍明显误判。该结果排除了“只因预热丢眼动”的解释，不能用输入完整代替模型效果验收。

实际连续JEPA训练范围与该任务当时提交的`continuous-supports.json`逐项匹配，包括源样本起止、允许更新索引及完整试次锚点。后、左、右在同一原始流中连续训练；前方向另段前后各保留5秒。表中的更新是100ms周期，彼此相关，不是独立样本。

- **前、后、左的连续训练任务起始没有预热缺口。** 例如后向任务开始后约0.3秒的眼动候选已进入模型及弱监督；旧按试次图会把它画成尚未预热。
- **右向有真实QC影响。** 任务后约0.872秒触发`F8:rms`拒绝，随后约0.972～2.272秒为状态重建，合计15次更新、约1.5秒。早先约0.472秒的明显候选已被保留并进入弱监督，但之后的信号不能当作全部可用。没有放宽质量门，也没有从原记录删除拒绝样本。
- **官方REST仅有旧片段，不能凭空补前史。** 任务开始时只有1秒已有输入，前4次任务更新约0.4秒仍处预热。其原始样本保留。
- **上轮额部轻量读出确有短窗问题。** 前、后、左约0.5秒初期未进入有效训练输出；右向叠加QC，前2秒仅4次有效训练更新。该分类器较高训练拟合并不证明它学到了完整起始眼动。

前置和回中候选若标注为UNKNOWN，会进入连续状态和特征，但不被当作REST或方向真值加入监督。它们可能通过后续状态影响预测；不能声称已经获得正确的回中／停止标签。此次尚未把自动候选强写成训练真值，也没有重训后宣称问题已消失。

连续诊断视图预先读取了真实已到达的前史，任务结束后继续处理实际尾部；测试5个任务内共695次有标签更新，额部支路均已具备输入条件。表中召回仅对联合任务指令评分，不是客观眼位准确率。向右约4.90%、向后0%的结果表明，现有分类头仍未通过方向识别核验。

原测试片段各自与canonical原始流逐值相同，证明没有原始文件丢样。问题在于旧派生裁剪和重置的位置：

- 前向任务前约0.9秒有明显额部瞬态，位于原裁剪之外。
- 右向任务前约1.272秒存在上一动作返回附近的瞬态，旧右向片段未包含；约任务后0.228秒还有另一瞬态，旧独立片段仍在预热。本次将双相变化分开标记，避免把“回中”和“新方向”合并成一个事件。
- 后向任务后约0.1秒的候选，旧独立片段仍在预热；连续诊断中输入已就绪，但新额部头当时更偏向右，而非后。
- 任务结束后的灰色是UNKNOWN标签，不表示信号消失。新图另列输入状态轨道，避免同一种颜色表达不同含义。

这些时间来自250Hz原始样本索引、100ms因果低通代理，含滤波和离散更新时间影响；不把它们冒称为精确扫视真起点。

## 眼动位置和持续方向标记

已给训练集和测试集全部10个试次保存信号曲线、候选区间、冻结分类头逐帧分数和方向证据持续区间。修订后共57个训练视图候选关联、31个测试视图候选关联，去掉相邻试次重复关联后为80个独立源峰值；它们是额部眼动样变化候选，不是已确认扫视数量。

输出同时保留以下不同信息：

| 信息 | 含义 |
|---|---|
| `sample_start / peak_sample / sample_end` | 原始流上的候选样本范围和峰值，可直接定位 |
| `phase`、相对任务秒数 | 相对按钮锚点的准备／任务／结束后位置，不是真实眼位起止 |
| `association`、`source_instruction_label` | 区分本试次任务、相邻其他试次和UNKNOWN上下文，避免把上一动作返回误标成新方向 |
| 输入状态 | READY、WARMUP、QC_REJECTED分别记录，UNKNOWN标签不等于不能推理 |
| `eye_scores`、方向持续估计 | 当前冻结头的五类分数及连续高分区间，不是眼位真值 |
| 直接监督／上下文资格 | 训练候选是否实际进入模型上下文、联合损失和眼动弱监督 |
| `human_review_status=pending` | 尚未人工确认；不会自动加入训练真值 |

方向持续区间仅在分数≥0.7、类别间隔≥0.15并连续3次新更新成立时输出，证据不足就结束，不把一次扫视无限延长为持续眼位。现有分类器使用头皮记录，且硬件高通与基线漂移会影响位置保持信息；没有同步眼动仪或独立EOG标定，不能从这些信号保证眼睛仍处某方向，更不能给出视线角度或屏幕坐标。

## 真实性与后续使用

所有真实信号处理、模型推理、候选标记及信号图均在指定A100执行。本轮梯度更新为0、没有拟合测试阈值或修正后追着测试结果改模型。候选阈值和噪声标尺先由训练集确定；二次标记仅将双相显著峰在谷值处拆开，旧标记保留，避免合并返回与新变化。这是可审阅检测规则，不是经眼位真值验证的成熟分类结果。

本轮已按你的明确要求读取测试集，并在A100及本机内部元数据保存`previously_inspected=true`、`independent_unseen_test_eligible=false`。旧测试文件和集合身份不变，也没有用于训练；后续不能再把它说成完全未查看的独立验收集。

141份既有来源文件、127个公开模型权重及当前私人模型／额部读出权重均核对不变。三集修正版文件哈希核对通过；模型库仍128项，当前所选模型未切换，推理和动作没有启动。最终聚焦测试、A100测试、来源核验和候选修订回执见证据包。

依据Malta官方EOG采集说明，向目标、返回和眨眼原本就是不同事件；头皮代理需要进一步核验，不能按按钮阶段自动推断这三种真值。[官方说明](https://www.um.edu.mt/cbc/ourprojects/eyecon/eogdataset/)

下一步应先在这些已定位的头尾区间逐一确认事件，再用训练角色重建完整的眼动事件／方向监督；新额部分类器也要使用足够前史或连续训练支持重新锁定协议。当前最明确的结论是：**原始眼动尚在，旧裁剪／读出预热和监督范围确有问题；已保存上下文与定位证据，但现有分类头的方向及持续空间识别仍未达标。**

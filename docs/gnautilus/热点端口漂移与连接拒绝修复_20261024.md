# 热点端口漂移与连接拒绝修复

## 原因

采集端截图报 `WinError 10061`，本地写盘正常。现场检查确认中枢进程和网页 8765 正常，但热点 WebSocket 实际在 60838，采集端仍连接约定的 8768。对 60838 的信息请求返回健康，8768 则拒绝连接。

旧实现对固定端口绑定异常直接回退到随机端口，UDP 发现也随之移动。固定地址客户端因此无法重连。旧代码没有保留第一次绑定异常，不能追溯其确切原因；未把它认定为设备断流或防火墙问题。

## 修改与恢复

- 固定端口绑定失败不再自动改成随机端口，每 500ms 在同一端口重试；显式指定 `port=0` 仍供隔离测试使用。
- 监听错误、请求／实际端口、UDP 发现状态和客户端数量进入 `gnautilus.lan_listener`，同时通过采集端反馈返回。
- 中枢无活动记录及动作时正常重启；8768 TCP、UDP 和 `192.168.137.1:8768/eeg/v1/lan/info` 已恢复。
- 实际采集电脑已建立热点连接，1.1.13 状态回传新鲜。检查时其状态为 `stopped`／`closed`，因此不能据此宣称新鲜 EEG 和连续打标已验收。

首轮端口修复只改中枢，1.1.13 可以重新连接。后续现场核查新增了下面的计时与模式恢复修复，采集端对应为 1.1.14。不需要修改公网服务、全局网络路由或重新配对。

## 回归

先用真实占用端口复现“静默换端口”的失败，再验证占用期间保留固定端口及可见错误、释放后自动恢复、显式临时测试端口仍可用。相关热点／公网链路、打标、历史隔离、32 路软件闭环等共 36 项通过。原始证据在本机 `outputs/lan_listener_fix_20261024/`。

## 2026-10-25 补充

现场 1.1.13 接收恢复后，无标签诊断记录保存了 1592 个真实样本／199 块，关闭清单无缺块；该诊断没有方向或 REST 标签，不用于训练。随后真实打标收到事件，但发生实时年龄超限，不能据此宣称完整打标已通过。

1.1.14 在数据中带上“收到当前票据以来经过的时间”，与数据自身年龄采用同一单调时刻计算。中枢用 `票据签发时间 + 客户端票据经过时间 - 数据年龄 - 2ms余量` 取保守的源时间下界，并检查经过时间不超过票据实际年龄；未知字段仍回退旧严格下界。老样本、未来时间和不合理经过时间不被恢复成新鲜数据，250ms 门槛不变。

标签心跳不再创建已经结束的会话。按用户随后明确的新要求，临时断流改为保留活动会话、关闭原标签区间并等待恢复，恢复后继续同一逻辑会话；具体设计见 `断流模式保持与自动恢复_20261025.md`。手动结束后仍不可由心跳重建。热点标签也不再错误使用公网时钟关联，而保存中枢接收位置及独立的客户端样本位置，时间语义不冒充硬件触发。

私有计算连接的恢复使用 Windows 凭据管理器保存凭据及核对 SSH／服务身份，网卡选择排除无上游网关的热点接口。只恢复原先选定的模型；未开启的推理不会因此启动，VR 动作仍须重新手动允许。

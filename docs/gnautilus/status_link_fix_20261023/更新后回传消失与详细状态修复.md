# 更新检查后回传消失与采集端详细状态

2026-10-23。Windows1.1.5／11005，Quest保持2.1.2。

## 截图问题的原因

截图日志中已出现“中枢连接测试完成”，但回传面板变成“等待连接”。旧实现未开始接收EEG时，只执行一次短连接探测，随后关闭连接；界面只显示5秒快照，过期后把记录、标签、VR和模型状态全部清空。点击更新并完成网络请求时，快照已经过期，因此产生“检查更新后掉线”的表现。

另外，旧更新线程判断安装条件时会再开一条新的身份探测连接；在每类设备仅一台的约束下，这种独立启动代次可能与已有连接竞争。问题并非证明服务器掉线或真实EEG断流，修复也不能通过永远展示旧快照来掩盖。

## 修复的连接逻辑

- 未接收EEG时，维持一条独立的控制状态连接，持续接收中枢签名回包。界面、连接测试和更新器共用该连接；更新HTTP请求独立运行，不刷新或清除中枢状态。
- 状态回包超过1秒或连接真正中断后停止显示新鲜状态，后台重连；EEG250ms新鲜度和动作180ms租约不变。客户端在线不等于EEG新鲜。
- 开始接收或历史补传前，在后台释放空闲状态连接，再交给数据传输连接，不让同一角色的两个启动代次相互争用。接收结束后恢复空闲状态连接。
- 空闲时明确显示“中枢在线 · EEG尚未开始接收”；云端保存与中枢持久化项显示“尚未采集EEG”，不再用等待数据确认冒充网络未连接。
- 原厂SDK、采集配置和设备启停职责不变；未启动接收时不加载SDK。

## 中枢中新增的详细信息

在原中枢页面的“连接信息”中新增15项状态行，沿用现有弹窗和样式，未重做导航、首页或模型页面：

| 类别 | 内容 |
|---|---|
| 身份与版本 | 采集电脑、客户端版本、角色身份、报告年龄与新鲜／过期标记 |
| SDK与接收 | 客户端阶段、SDK状态、选择的序列号与实际取数序列号分别显示 |
| 实际数据布局 | EEG路数／总列数、单位、附加通道、原厂配置采样率、流身份、epoch和配置摘要 |
| 保存与积压 | 本地已提交样本／块、磁盘状态、写盘队列、待中枢确认块、持久化连续前缀 |
| 网络与更新 | 实际连接路径、软件更新阶段、最近异常 |
| 未测量项目 | 未取数时通道和采样率未知；主机实测采样率及接触质量仍未知 |

数据来自已认证采集端的白名单字段，中枢记录接收时间并计算年龄。客户端报告与中枢实际接收到的EEG状态分开，不依赖客户端时钟声称在线。过期后保留明确标记的历史报告，便于定位故障。网络协议不新增任意URL、端口或内网访问能力；状态不转发秘密、完整本地路径或原始设备配置。

旧1.1.4不会发送完整状态结构，需升级到1.1.5后才能显示全部字段，不能替旧客户端猜填信息。公开无认证健康接口不展示这些设备明细；明细在本机中枢的已有管理入口查看。

# 局域网连续接收与 A100 自动恢复（2026-10-29）

## 已定位的问题

现场同时存在三个 `scripts/start_hub.py --worker` 实例。局域网 8768 由一个实例接收 `192.168.137.181` 的真实 EEG；网页 8765 却可能由另一个实例回答，返回零样本和 8768 端口占用错误。Windows 的地址复用允许这几个网页监听并存。已保留接收数据的实例、停止另外两个实例，并核对恢复后的真实样本增长。

第二个问题独立存在：旧 `_tick()` 将超过 250ms 的数据年龄直接当作源丢失，每次清空窗口、增加 source_epoch、使模型重建。修复前约 64 秒观察到 6 次恢复、没有序号缺口，符合将迟到误作不连续的程序路径。

A100 已保存本机凭据，后台并非完全没有重试，但网页隐藏了真实连接阶段，并以“新模型未配置”替代计算状态；公网状态还覆盖私有 SSH 状态。本机另有 `172.25.56.83/32 → 172.28.64.1` 固定路由，当前 WLAN 为 `192.168.0.103`、上游网关 `192.168.0.1`。现场物理路径超时，系统路径也未完成有效 SSH 握手。不能将这种网络失败报告成 GPU 服务在线。

## 本轮修改

- `hub/instance.py`：操作系统文件锁在创建 Hub 前取得；网页端口使用独占绑定，并在任何设备／模型资源初始化前预留。锁在进程退出时由系统释放，不依赖删除 PID 文件。重复启动不会启动第二套采集、模型或中继线程。
- `hub/app.py`、`hub/lan_ws.py`：网页与 LAN 信息接口分别返回进程 PID，便于证明两端属于同一个实例。启动健康探测显式绕过系统 HTTP 代理。
- `hub/gnautilus_runtime.py`：250ms 只判断动作证据是否新鲜；短时迟到不重建 epoch、不清空窗口、不关闭标签区间。持续 3 秒没有接纳数据才进入输入等待；保留模式与上次波形，在后续新数据到达时重建连续窗口。真正缺包、计数异常、配置／设备身份改变仍重建对应证据，不能跨断点伪造连续数据。
- `gnautilus_acquisition/timing.py`、`lan_client.py`、`hub/gnautilus.py`：局域网按序数据提供 3 秒有界交付窗口，维持流水发送、有界在途块和本地原始日志补传。迟到块能进入保存与连续模型处理；这不把它变成可执行动作。明确的 backfill 仍只保存，不能刷新实时输入。旧版采集端仍有 180ms 的发送筛选，完整交付改进需升级 1.1.16；中枢本身对旧版也不再因短暂迟到反复重置。
- `hub/ml_runtime.py`：迟到推理保留已消费样本位置和远端 generation，不因迟到重新启动整个分类器；返回状态为 delayed，fresh=false，不能驱动动作。新鲜输入到来后继续同一模型状态；真正间断／模型改变才重建。显式停止、急停不自动撤销。
- `gnautilus_ml/ssh.py`：配置的物理路径失败后尝试系统路由；两条路径均核对同一固定 SSH 主机身份及服务/GPU身份。TCP 尝试有超时，公开连接阶段、尝试次数、耗时、错误与退避时间。失败不删除有效凭据；认证或身份错误单独处理。重试最多退避 15 秒，不启动训练或选择其它模型。
- `hub/web/app.js`、`gnautilus-ml.js`、`intent.js`：保留原导航和布局。迟到波形留在原位置，明确标为上次样本；计算连接显示真实阶段和重试信息，公网状态不再覆盖 SSH 状态；推理 delayed 状态明确显示为保持运行。

## 真实设备观察

中枢加载新逻辑后，使用已经运行的真实采集端，不向生产注入模拟信号。约 128.81 秒的 120 次轮询中：

|项目|结果|
|---|---|
|实际数据合同|32 EEG 加 LINK／DIGITAL，共 34 列；配置 250Hz，通道位置仍待实测确认|
|新增样本|32,178|
|source_epoch|始终为 1|
|恢复次数／序号缺口|0／0|
|波形窗口|750 行，持续有实际变化|
|250ms 动作时效|119 次轮询为新鲜；一次迟到未引发窗口重置|
|进程身份|网页与 LAN 同一 PID；额外启动 `python -m hub.app` 被锁拒绝|
|A100|自动连接次数从 3 增至 7，仍未完成有效 SSH 握手，不记连通通过|

此观察验证真实采集到本机的接收与显示，不等于模型识别或 Quest 执行动作验收。未替用户开启新的打标或推理任务，未启动训练。

## 网络修复边界

尝试添加只针对 A100 的临时主机路由时，Windows 返回“拒绝访问”，未修改任何路由。已提供 `scripts/repair_compute_route.ps1`，在管理员 PowerShell 中执行：

```powershell
& 'C:\Users\19410\Desktop\EEGMovement\scripts\repair_compute_route.ps1'
```

脚本只为配置中的 A100 主机添加当前物理上游网关的 ActiveStore 路由，记录原始状态；不改默认路由、VPN 或永久路由。`-Restore` 只移除本脚本添加的临时规则。当前网络本身必须能到达校园私网；修正本机下一跳不能创造校园网访问权限。公网中继仍不能访问 A100。

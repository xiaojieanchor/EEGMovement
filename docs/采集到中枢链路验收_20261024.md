# 采集端到中枢的软件链路验收（2026-10-24）

当前版本：1.1.8。用户已拔下 SDK／设备，本轮验收使用明确标记的合成数据，不代表真实 EEG、接触质量或运动意图识别验收。

## 本轮修复

- 将原厂 SDK 初始化等待与运行后无样本看门狗分开：初始化有界等待 15 秒，开始取数后仍为 5 秒无样本停止。启动等待不授予数据新鲜度或模型权限。
- 正常窗口入口支持显式 --start-receiving；默认仍只打开工作台。增加实际 GUI 入口测试，覆盖参数传递和运行状态文件。
- 安装器记录失败进程退出码、健康回执路径和启动日志。新增本地构建安装入口，逐文件核对复制内容，健康失败回退原版本，保留已签名更新的版本序号及验签规则。
- 公网控制、数据、补传三个通道分别显示网络、TLS 和身份认证阶段，避免连接建立期间只有笼统等待。
- 中枢反馈增加有界的采集、标签和存储日志；记录事件先写盘，再形成日志。客户端按中枢启动身份和日志序号去重，断线重连不会重复刷屏；兼容尚未带此字段的旧中枢。

## 隔离端到端验收

在本机隔离的真实 TLS/WSS 服务中，通过生产 Replicator → RelayServer → HubRelay → GnautilusRuntime → GuidedAcquisition 路径：

- 验证 32 路 EEG 加 LINK、DIGITAL 两列，共 34 列的推送、实时接收和连续保存确认。
- 在测试夹具中注入 live 合同和合成数组以覆盖打标路径，不连接任何原厂设备或生产个人记录。
- 验证 LEFT 按住事件绑定真实接收位置、标签状态及保存计数回传，松开后标签为空／UNKNOWN，不填成 REST。其它方向与显式 REST 由标签调度及主动采集回归覆盖。
- 验证记录结束后 raw.f32 行数、数值、events.jsonl 中标签，以及 closed.json 中原始数据和事件文件的 SHA256；验证中枢关闭记录日志回传到采集端。
- 已有回归覆盖重连补传、去重、乱序、过期实时数据隔离、错误身份、磁盘失败、断流结束标签会话等边界。

实际公网测试验证了远端收包和数据落盘确认；打标、记录关闭与新增详细日志在隔离端到端测试中验收。没有宣称替生产中枢开启个人采集或操作头显。

## 正常使用

1. 使用桌面“EEGMovement采集工作台”启动新版。原厂设备未连接时，工作台应能连接中枢、显示状态和通信日志，EEG 波形仍等待真实输入。
2. 设备接回后，原厂软件建立非独占会话，配置 Electrode 并开始采集，再在工作台发现设备和开始接收。
3. 观察本地保存、云端缓存和中枢确认三个计数。中枢确认持续增长才表示远端已经提交保存；只显示公网认证不能当成数据已到中枢。
4. 在中枢或 VR 按既有流程开始主动采集、显式打标。未标注和松开保持 UNKNOWN，接触质量未知不自动变合格。
5. 先结束主动标签与记录，再结束采集端接收；原厂设备启停仍由原厂窗口负责。

中枢电脑也需要 git pull 同一版本，再通过原有 Hub 启动入口重启，才能回传本轮新增的详细采集／标签／保存日志。采集端兼容旧中枢的状态摘要。此采集电脑不用启动第二个 Hub，也不需要连接私有计算节点。

## 开发与本地恢复入口

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/build_gnautilus_acquisition.py
.\.venv\Scripts\python.exe scripts/install_local_acquisition.py
# 显式要求打开窗口后开始接收时才增加 --start-receiving；没有设备时不要增加。
# 如需本机运行诊断，增加 --status-file outputs/runtime-status.json。
```

本地安装入口仅处理本机可信构建目录，不接受或伪造远程签名。远程升级继续使用原有验签与防降级流程。--status-file 输出不含原始样本、私钥或连接凭据，带 PID 和更新时间用于识别陈旧状态；文件留在本机。

无设备时的软件回归结果，不替代设备接回后的持续原厂取数、现场网络和 VR 验收。


## 冻结程序 TLS 运行环境修复

本机 Python 发行版在 SSLContext 初始化时读取 codex-rejected-cas.pem。此前 PyInstaller 没有复制这份公开的运行时资源，导致冻结程序在创建 TLS 上下文时抛出 FileNotFoundError，尚未到证书校验或认证阶段。构建现在按所用 Python 运行时实际存在的资源原样打包，记录 SHA256，并增加 --tls-smoke-test 及冻结 EXE 的私有 CA 上下文检查。未移除或放松主机名、证书及应用专用 CA 校验。

资源补齐后，现场安装版在无设备状态下已收到当前实际中枢的新鲜签名回包。正常窗口启动与 SDK 取数分开；无设备状态不会生成演示波形、启动个人采集或模型。
